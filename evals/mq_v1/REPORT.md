## 1. 教材解析和 JSON 保真

脚本识别 H1 单元中最后的 `## meta question`，以 H3 分题。题干、选项、答案和解答分别保存 Markdown；代码和 Mermaid 不改写，PNG/Wikilink 图片保存文件引用、哈希和所属字段。

本次 30/30 道题的类型、题干、选项、答案及解答与事先编写的预期数据完全一致；2/2 个无题单元被跳过，8/8 个图片题附件可以加载。正文哨兵文本没有混入任何题目。代码围栏、引用内的伪标题、重复题名、非末尾 MQ、缺失附件等另有机械测试。

修复了一个真实基础缺陷：合法 JSON 字符串内部的 Markdown 代码围栏过去会被错误剥离。现在先解析 JSON，只允许移除整个响应的外层 JSON 围栏。

## 2. rubric 生成

原开发集只有 20/30 份 rubric 通过结构校验。问题包括知识点缺少 `definition`，以及给单选题加上不适用的 `blank_id`。保留全部失败记录后，仅根据开发集增加必填字段和题型约束说明；6 次小样本复验通过。

正式集 **60/60 份 rubric 结构有效**。但结构正确不代表评分规则合理：对照教材与冻结标准复核，**11/60 份**存在部分分过严或未量化的问题，详见 [rubric-review.json](rubric-review.json)。

具体例子：

- U3Q4 第 0 次：只回答列表共享关系、没有回答复制关系时，模型规则给 0；冻结标准给 0.5。
- U4Q2 三次：只说明二分查找的有序前提时，模型规则均规定 0；冻结标准给 0.5。
- U4Q3、U5Q3：定义或结论只答出一部分时，同样出现全部扣除。
- U5Q4 第 1 次：“列出算式但未给结果”只写可给部分分，未给明确分值。

本次复核未发现这些 rubric 的必要知识要点缺失，但部分分策略未通过要求。该复核由本任务助手对照预写标准完成，**没有外部人工双标**；不是用被测模型给自己的 rubric 打分。

## 3. 开放答案评分

A 组使用固定标准 rubric；B 组使用各次模型生成的 rubric。两组使用生产评分函数、原参考答案及解答；图片题传入真实图片。分数按 0–1 归一化。

| 正式集指标 | A：标准 rubric | B：生成 rubric | 预设门槛 |
|---|---:|---:|---:|
| 有效评分 | 165/165 | 165/165 | 无无效输出 |
| 总分 MAE | **0.0121** | **0.0394** | ≤0.10 |
| 误差不超过 0.10 | 97.58% | 92.12% | ≥90% |
| 三次评分差不超过 0.10 | 54/55，98.18% | 53/55，96.36% | ≥95% |
| 多给分 / 少给分 | 0 / 4 | 1 / 12 | 分别报告 |
| 空答或注入类样本得到实质分 | 0 | 0 | 0 |

A 组逐项归一化 MAE 同为 0.0121。B 相对 A 的 MAE 增加 0.0273，未超过预设 0.05。

**整体平均掩盖了差异。** 纯文本 B 组的误差容差达标率只有 **87.62%**，重复稳定率 **94.29%**，两项均低于门槛；带参考答案的图片题在 A、B 两组均无评分误差，抬高了汇总结果。

值得复现的失败：

- U4Q2 的正确改述“排序保证被舍弃区域不含要找的值”，A 组三次均只给 0.5，标准为 1。
- U4Q2 的部分答案“数组已排序”，B 组三次分别给 **0、0、1**，标准为 0.5。生成规则本身过严，评分执行又发生漂移。
- U3Q5 的正确 FIFO 改述，也出现被少给 0.5 分。

逐题结果见 [正式集 failures.json](runs/formal-v1/failures.json) 和 [summary.json](runs/formal-v1/summary.json)。这些重复调用共享题目，不能视为 165 个相互独立的题目，也不能据此外推总体误差置信度。

## 4. 视觉能力：作答与评分分开看

### 正式诊断

6 道正式图片题各重复 3 次，看图作答 **17/18 正确，94.44%**。一次错误为 U5Q5：已正确读出 A=7、B=2，却把 B−A 算成 +5。

移除图片后，仅 **12/18** 次明确表示证据不足，其余请求仍给出答案。图片替换配对和无图对照表明，不能只看正常请求的准确率。

无具体参考答案的视觉判分：36 次请求中 **32 次有可用分数、4 次输出截断**；有效结果 MAE 为 **0.2031**，超过 0.10。11 次多给分。典型结果为 `score=0.5`，理由却明确写“两项都错误，应得0分”；还出现 `score=1`、理由称学生选错应得0分。

这组诊断使用直接总分输出，同时移除了具体参考答案，**不能把与 A/B 的差距全部归因于视觉能力**。

### 控制输出格式的探索性补测

为检查上述混杂因素，额外 72 次请求使用生产的逐项评分函数，后端计算总分；两臂提示相同，只有是否附图不同，且均不提供图中具体答案。

| 条件 | 请求 | 有效评分 | 明确证据不足 | 有效评分 MAE |
|---|---:|---:|---:|---:|
| 实际附图 | 36 | 25 | 11 | **0.12** |
| 移除图片 | 36 | 0 | 36 | 不适用 |

有效的有图评分中 22 次完全正确，另 3 次少给分。图像发送审计确认全部 36 个有图请求包含图像块、36 个对照请求均不含图像块，见 [传输审计](runs/vision-criteria-followup/transport-audit.json)。

改成逐项评分减少了矛盾总分，但模型仍会在确实有图时拒评，并存在误评分。补测是看到正式结果后开展的探索性分析，没有替换主结果，也不是新的独立测试集。

## 5. 结论和使用边界

1. **固定 Schema → 原题 JSON 导入可用。** 题目和 Markdown 内容保真，无题单元不产生题目。
2. **标准 rubric + 参考解答 + 逐项后端加总**在这份小型数据集上表现较好，但仍会误扣正确改述的分数。
3. **生成 rubric 不宜仅凭结构校验就认为评分规则合格。** 应优先把部分分拆成明确的原子条件和数值，再评测等价改述。
4. **独立视觉评分未通过。** 需要保留证据不足状态，避免在无图或读图不可靠时强行给学生记零分。
5. 本轮未测试新题变体生成、真实学生长期学习效果或大规模题库迁移。测试教材与标准作答是本任务预先编写的合成集，未经外部专家双标。

评分门槛是本轮预先声明的工程验收标准；报告保留所有失败，未为提高指标而改动正式题目、标准答案或评分标签。
