# 强化学习教材：80 题批量测评报告

## 结论

**本轮教材的 80 道原题完整提取，最终 80 份 rubric 与预写评分依据一致，题库已通过生产构建与持久化检查。** 首轮 rubric 生成有 1 次非法 JSON，单题重试恢复。最终 96 次开放题评分中 **95 次与预写分数完全一致，1 次多给 10 分**；达到预设误差门槛，但仍存在矛盾答案误判。

这是合成教材和合成作答上的测评。审核由主 agent 完成，不是独立人类专家双标；不声称能直接代表真实学生作答质量。

## 1. 教材与审核

按用户指定，由 **GPT-6 Luna** 编写教材，主 agent 阅读全部章节和 80 道题后复核、要求修订。最终 [教材](book.md) **1,729 行、8 个 H1 章节**，每章最后一个 H2 都是 `meta question`，各有 10 个 H3 原题：

| 内容 | 数量 |
|---|---:|
| 单选题 | 32 |
| 填空题 | 24 |
| 解答题 | 24 |
| 总计 | 80 |

章节覆盖问题建模、MDP/Bellman、动态规划、MC、TD/SARSA/Q-learning、DQN、策略梯度/Actor-Critic，以及探索/评估/奖励设计。

审核阶段修正了折扣推导的前提、终止与时间截断的区别、TD 错误项可能向上或向下偏、GAE 与价值回归目标的区别、重复评分点，以及单选答案位置全部相同的问题。一次修订丢失章节结构也在冻结前被 8 单元检查拦截并恢复。完整记录见 [逐题源内容审核](source-review.json) 与 [Luna 作者说明](author/review-notes.md)。

主 agent 另加入了原题中的 Mermaid 和数值表格，检查 Markdown 保真；没有更改对应题目的答案。17 道数值题独立重算全部通过，见 [算术核查](arithmetic-check.json)。关键概念核对参考 [Spinning Up：RL 概念](https://spinningup.openai.com/en/latest/spinningup/rl_intro.html)、[策略梯度推导及 baseline](https://spinningup.openai.com/en/latest/spinningup/rl_intro3.html) 和 [早期深度 Q 学习论文](https://arxiv.org/abs/1312.5602)。

教材、独立源题清单、逐题审核、96 条测试作答都在模型调用前写好并冻结哈希。预期字段来自作者的独立数据结构及主 agent 复核，**不是由被测解析器反向生成**。

## 4. 实际试评分

每章选 Q08、Q10，共 16 题，每题预写完整、英文等价改述、基础、进阶、错误、矛盾六种作答，共 96 条。基础、进阶分别预期 20、50 分；完整和改述 100 分；错误 0 分；否认第一条但其余正确的矛盾答案 90 分。

第 1 章为开发集；其余 7 章为测试集。每题固定同一份 rubric，开发集重测也复用原 rubric，避免把生成规则的变化混入评分比较。

| 分组 | 有效评分 | 完全一致 | 平均绝对误差（满分100） | 分差≤10 |
|---|---:|---:|---:|---:|
| 修复后的开发集 | 12/12 | 12/12 | 0 | 100% |
| 测试集 | 84/84 | 83/84 | 0.119 | 100% |
| 最终合计 | 96/96 | 95/96 | 0.104 | 100% |

16/16 题的基础、进阶、完整作答得分严格递增；16 个完全错误作答全部为 0 分。全部英文等价改述得满分。另对 32 道单选和 24 道填空做了 **283 次本地确定性评分检查**，覆盖错误选项、空答、别名和数值容差，全部通过，见 [检查结果](objective-grading.json)。这些本地检查不计入模型调用数。

### 开发时修复的问题

初始开发集 `RL01Q10-contradiction` 同时肯定和否定 episodic 有终点，模型只引用正确片段，给了 100 而非 90。评分 prompt 补充“逐项检查整个答案、特别是后文否定”的指令与开发例子；同一份 rubric 重测 12 条全部符合标准。此后没有根据测试集结果继续改 prompt。

### 仍存在的评分错误

测试集 [RL02Q10-contradiction](runs/final-v3/grades/RL02Q10-contradiction.json) 先提出应列出当前观测字段，又声称完全没必要列出。模型看到了后面的说法，却判断它不否定该评分项，最终给 **100，预期为 90**。这属于对步骤必要性冲突的评分执行偏差，说明矛盾识别尚不完全可靠。

该样本达到了事先设定的“误差不超过10分”门槛，但报告仍明确保留偏差，没有把它写成完全正确，也没有修改预写标签。

## 5. 实现修复、调用成本与复现

此次实际发现并修复一个生产缺陷：带数值容差的填空题以前忽略了显式字符串别名，导致答案键接受的 `3/4` 被拒绝。现在先匹配显式别名，再尝试数值容差；已补充小数、分数、空答、错误值和非有限数回归。

工程验证：`python -m pytest pen/tests -q` **1,224 项通过**；`git diff --check` 通过；最终冻结教材再次核对为 80 题、无字段差异。

新增批量测评入口，保留数据/代码哈希和原始模型请求。新增统计回归确保缺失、失败样本不会从通过率分母中消失；缓存重放必须验证完整请求签名，不会隐式重新调用模型。

- 模型：请求及响应均记录为 `deepseek-flash`，thinking off、temperature 0，输出上限 4096 tokens，并发 4。
- **真实调用 189 次，总 tokens 1,923,816**，低于 240 次 / 600 万 tokens 上限。
- 构成：81 次 rubric 生成（含1次恢复）＋108 次评分（开发12次旧版、12次修复版、测试84次）。
- 最终运行复用79份已生成 rubric和12条修复后开发评分；这些重放不计作新增调用。
- 原始调用中的密钥扫描通过。没有修改上一轮的测评结果。

运行记录：`baseline-v1` 保存初始开发结果；`contradiction-v2` 保存开发修复与首次其余70题生成；`final-v3` 保存单题恢复、最终试评分及生产持久化结果。每份复用记录注明 `call_run` 指向原调用所在运行。

离线核对：
