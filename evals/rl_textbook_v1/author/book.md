# 第1章 强化学习问题的骨架
## 本章定位
- 强化学习研究的是序列决策：智能体先行动，环境再反馈，下一步又依赖之前留下的状态。
- 监督学习通常从固定样本学映射；强化学习的样本由策略自己诱发，所以数据分布会随学习改变。
- 一个任务是否适合强化学习，先看它是否有动作、反馈延迟、长期目标和可重复交互。
- 奖励不是人类愿望的完整表达，而是算法可见的局部信号；把愿望压成奖励会丢信息。
- 本章只建立问题语言：状态、动作、奖励、策略、回报和马尔可夫性。
- 后续算法的差别，几乎都能还原为怎样估计回报、怎样改进策略、怎样处理未知环境。
## 交互流程图
```mermaid
flowchart LR
A[智能体] -->|动作 A_t| E[环境]
E -->|状态 S_{t+1} 与奖励 R_{t+1}| A
```
图中箭头表示时间上的因果顺序：动作先发生，奖励和下一状态随后到来。
## 核心概念
- 状态是决策所依据的信息摘要；观测是传感器给出的数据，两者在部分可观测任务中并不相同。
- 动作是智能体能控制的选择；动作空间可以是离散按钮，也可以是连续控制量。
- 奖励是每一步的标量反馈；它可以稀疏、延迟、带噪声，也可能被错误设计。
- 策略 π(a|s) 给出在状态 s 下选择动作 a 的概率；确定性策略只是概率集中在一个动作上的特例。
- 轨迹是状态、动作、奖励的时间序列，记作 S0,A0,R1,S1,A1,R2,...。
- 回报 G_t 是从时刻 t 往后的折扣奖励和，常用 G_t=R_{t+1}+γR_{t+2}+γ^2R_{t+3}+...。
- 折扣因子 γ 越小，学习越偏向近期奖励；γ 越接近 1，远期结果越重要。
- 终止状态结束一条轨迹；到达后通常没有后续奖励或价值。
## 建模步骤
- 先写清智能体是谁，避免把环境内部机制误当成智能体动作。
- 再列出真正可选的动作，区分“想要发生的结果”和“能执行的控制”。
- 状态应包含预测未来奖励所需的信息；缺失关键信息会破坏马尔可夫性。
- 奖励要对齐任务目标，但也要考虑代理行为是否会利用漏洞。
- 时间步的粒度需要稳定：过细会拉长信用分配，过粗会隐藏关键决策。
- 初始状态分布影响训练难度和评估意义，不能默认所有状态同等常见。
- 如果任务有自然结束点，优先建成 episodic；没有结束点时再考虑 continuing。
- 每个建模选择都应能解释“算法看到什么、选择什么、因为什么被评价”。
## 回报与目标
- 强化学习最大化期望回报，不是保证每条轨迹都获得最高奖励。
- 随机环境中，单次失败不必然说明策略差；要看多次轨迹的平均表现和方差。
- 折扣不仅是数学技巧，也可以表达任务对时间偏好的假设。
- 有限期任务可以用未折扣回报；继续任务常用折扣或平均奖励避免无穷和发散。
- 稀疏奖励让探索更难，因为许多动作序列在早期看起来同样没有价值。
- 塑形奖励能加快学习，但必须避免改变最优策略。
- 惩罚也属于奖励信号；大量负奖励可能让智能体学会尽快结束任务。
- 评价指标可以不同于训练奖励，但两者差距越大，部署前验证越重要。
## 常见误区
- 把奖励写成“看起来合理”的分数，而没有检查极端策略会怎样利用它。
- 把当前观测直接叫状态，却没有确认它足以预测下一步。
- 把动作定义成环境结果，例如“成功拿到物体”，而不是机器人能执行的控制。
- 只看即时奖励，忽略一个动作对以后机会的影响。
- 在离线日志上评估新策略，却忘了日志策略可能从未尝试某些动作。
- 把探索造成的短期损失误判为算法退化。
- 用训练回报作为唯一证据，忽略独立种子、置信区间和未见场景。
## 复习清单
- 能指出一个任务里的智能体、环境、状态、动作、奖励。
- 能区分即时奖励 R 与长期回报 G。
- 能解释为什么同一个奖励函数可能诱导非预期行为。
- 能判断一个观测是否可能缺少马尔可夫信息。
- 能写出折扣回报的前三项。
- 能说明 episodic 和 continuing 任务的差别。
- 能用自然语言描述策略 π(a|s)。
- 能把建模选择和后续算法风险联系起来。

# 第2章 MDP 与 Bellman 方程
## 本章定位
- 马尔可夫决策过程把强化学习任务写成可分析的五元组：状态、动作、转移、奖励和折扣。
- MDP 不要求环境确定，只要求当前状态和动作足以描述下一步分布。
- 价值函数把“从这里开始有多好”压缩成数值，是多数算法的中间语言。
- Bellman 方程把长期价值拆成一步奖励加下一状态价值。
- 这一拆分是动态规划、TD 学习和许多深度 RL 目标的共同骨架。
- 本章重点是读懂方程中每个期望、最大化和条件的含义。
## 对象速查表
| 对象 | 定义 | 用处 |
|---|---|---|
| V_pi(s) | 从状态 s 按策略 pi 行动的期望回报 | 评价状态好坏 |
| Q_pi(s,a) | 在 s 先做 a 再按 pi 行动的期望回报 | 评价动作选择 |
| P(s'|s,a) | 状态转移分布 | 描述环境动态 |
| r(s,a) | 一步期望奖励 | 描述即时反馈 |
## MDP 元素
- 状态空间 S 可以有限、可数或连续；算法实现时常需要近似。
- 动作空间 A(s) 可以依赖状态，例如非法动作在某些状态不可选。
- 转移概率 P(s'|s,a) 描述做动作 a 后进入 s' 的概率。
- 奖励函数可以写成 r(s,a)、r(s,a,s') 或随机奖励分布，取决于建模细节。
- 策略 π(a|s) 与转移 P 共同诱导轨迹分布。
- 初始状态分布决定一轮任务从哪里开始，也会影响总体性能指标。
- 折扣 γ 与任务时间尺度相关，不是随意调参。
- 终止状态可看作吸收状态，其后价值通常为 0。
## Bellman 期望方程
- V_pi(s)=E_pi[R_{t+1}+γV_pi(S_{t+1}) | S_t=s]。
- 外层期望同时覆盖策略随机性、环境转移随机性和奖励随机性。
- Q_pi(s,a)=E[R_{t+1}+γE_{a~pi}Q_pi(S_{t+1},a) | S_t=s,A_t=a]。
- V 与 Q 的关系是 V_pi(s)=sum_a π(a|s)Q_pi(s,a)。
- 期望方程评价固定策略，不主动寻找更优动作。
- 如果策略改变，价值函数也随之改变。
- 方程左右两边是同一个未知函数，因此可以用迭代方法求解。
- Bellman 备份就是用右侧表达式更新左侧估计。
## Bellman 最优方程
- 最优状态价值满足 V_*(s)=max_a E[R_{t+1}+γV_*(S_{t+1}) | s,a]。
- 最优动作价值满足 Q_*(s,a)=E[R_{t+1}+γmax_{a'}Q_*(S_{t+1},a') | s,a]。
- max 表示下一步以后按最优方式选择动作，不是对随机下一状态取最大。
- 从 Q_* 得到贪心策略通常直接选 argmax_a Q_*(s,a)。
- 若多个动作并列最优，任意并列动作或其混合都可以是最优策略。
- 最优方程非线性，因为 max 作用在未知价值上。
- γ<1 的有限 MDP 中，Bellman 最优算子是压缩映射。
- 压缩性解释了反复备份为什么能收敛到唯一固定点。
## 计算提醒
- 一步确定转移时，期望会退化成单个下一状态的数值。
- 多下一状态时，要用概率加权，而不是挑最好的下一状态。
- 奖励索引 R_{t+1} 对应从 S_t,A_t 到 S_{t+1} 的那一步。
- 不要把 V_pi 和 V_* 混用；前者评价固定策略，后者评价最优可达表现。
- 表格型 MDP 可以把每个状态的 Bellman 方程写成线性方程组。
- 价值单位与奖励单位一致；γ 只改变时间权重，不改变奖励含义。
- 终止状态价值若设为 0，要确认最后一步奖励没有被漏掉。
## 复习清单
- 能写出 MDP 的五元组并解释每个元素。
- 能区分 V_pi、Q_pi、V_* 和 Q_*。
- 能说明 Bellman 方程如何拆分长期回报。
- 能看出期望覆盖哪些随机来源。
- 能解释最优方程中的 max 是对动作取最大。
- 能手算一个确定转移的一步价值。
- 能指出非马尔可夫建模会让 Bellman 方程失效。
- 能把 Bellman 备份和后续算法更新联系起来。

# 第3章 动态规划：已知模型下的规划
## 本章定位
- 动态规划假设 MDP 模型已知，因此可以不采样真实交互而直接计算价值。
- 它不是大规模未知环境中的默认解法，但提供了许多 RL 算法的理想版本。
- 策略评价计算固定策略的价值，策略改进用价值构造更好的策略。
- 策略迭代交替评价和改进；价值迭代把评价截短并反复做最优备份。
- 本章关注表格型有限 MDP，目的是理解备份、收敛和误差。
- 一旦模型未知，后续章节会用采样估计这些备份。
## 策略评价
- 输入是固定策略 π、转移概率、奖励函数和折扣因子。
- 同步评价用上一轮所有状态的旧价值计算新价值。
- 异步评价可以逐个状态更新，只要更新覆盖充分也能收敛。
- 每次更新都是 Bellman 期望备份。
- 评价停止常看最大状态变化量是否小于阈值。
- 阈值越小，评价越准确，但计算更多。
- 终止状态价值应按建模约定固定，通常为 0。
- 评价只告诉当前策略好坏，不会自动改策略。
## 策略改进
- 改进步骤在每个状态选取让一步期望回报最大的动作。
- 如果新策略对所有状态都不差于旧策略，则称为策略改进。
- 贪心动作基于当前价值估计，估计越准确，改进越可靠。
- 若改进后策略不变，策略已经对当前价值贪心，通常达到最优。
- 策略迭代可使用精确评价，也可使用有限轮近似评价。
- 广义策略迭代概括了评价和改进互相追赶的过程。
- 许多采样 RL 算法也可看成广义策略迭代。
- 改进时要保留合法动作约束，不能对不可执行动作取最大。
## 价值迭代伪代码
```text
重复直到收敛:
  对每个状态 s:
    V[s] <- max_a sum_{s'} P(s'|s,a) [r + gamma * V[s']]
返回对 V 贪心的策略
```
这段伪代码把策略改进嵌入每一次最优备份。
## 误差与收敛
- 折扣最优 Bellman 算子的压缩性保证价值迭代会靠近 V_*。
- 一次备份会把未来估计误差最多乘以 γ 传回当前。
- γ 越接近 1，远期影响越强，收敛通常越慢。
- 残差小不等于策略表现完全最优，但可给出误差上界。
- 过早停止可能得到看似稳定但次优的策略。
- 状态空间很大时，完整扫描每个状态的成本会很高。
- 模型误差会传入规划结果；规划只对给定模型最优。
- 确定性模型中的 max 不应替代随机模型中的概率加权。
## 常见误区
- 把动态规划当作无模型算法；实际上它需要转移和奖励模型。
- 在策略评价里误用 max，导致评价固定策略时偷偷变成最优备份。
- 在价值迭代里只更新访问过的状态，却声称完成了全表规划。
- 忽略非法动作，使贪心策略选择现实中不能执行的动作。
- 只报告价值收敛，不检查贪心策略是否改变。
- 用过大的停止阈值，导致最后几步奖励差异被淹没。
- 把同步和异步更新结果的中间值直接比较，却忘了更新顺序不同。
## 复习清单
- 能写出策略评价的 Bellman 期望备份。
- 能说明策略改进定理的直觉。
- 能区分策略迭代和价值迭代。
- 能手算一个状态的一次 DP 备份。
- 能解释停止阈值与误差的关系。
- 能说明动态规划为什么需要模型。
- 能指出价值迭代中 max 的位置。
- 能把 DP 与后续 TD 更新联系起来。

# 第4章 Monte Carlo 方法：从完整轨迹学习
## 本章定位
- Monte Carlo 方法不用已知模型，而是等待完整 episode 结束后用实际回报学习。
- 它直接采样 G_t，因此目标直观，但必须等到终局才能更新。
- MC 适合 episodic 任务，尤其是模型未知而完整轨迹容易获得时。
- 与 TD 相比，MC 不自举，偏差较小但方差可能更大。
- 本章重点是访问定义、增量平均、MC 控制和重要性采样。
- 理解 MC 有助于理解采样估计和策略分布差异。
## 预测问题
- first-visit MC 只使用一个 episode 中某状态第一次出现后的回报。
- every-visit MC 使用一个 episode 中该状态每次出现后的回报。
- 在足够采样下，两者都可估计状态价值。
- MC 目标是完整回报，所以不需要下一状态价值估计。
- 没有自举意味着早期价值估计不会直接污染目标。
- 完整回报包含后续所有随机性，因此单次样本可能波动很大。
- 增量平均可避免保存所有历史回报。
- 非平稳任务中可用常数步长让新样本权重更大。
## 控制问题
- MC 控制学习动作价值 Q(s,a)，因为改进策略需要比较动作。
- 若只评价 V(s)，通常还需要模型才能知道哪个动作更好。
- 探索起点假设每个状态动作对都有可能作为 episode 起点，但现实中常不满足。
- 更常见做法是使用 epsilon-greedy 保证所有动作有非零概率。
- on-policy MC 控制评价并改进同一个带探索策略。
- 策略可以逐渐降低 epsilon，但过快降低会丢失探索。
- GLIE 思想要求无限探索且最终贪心。
- MC 控制的更新频率受 episode 长度限制。
## 增量平均代码
```python
count += 1
value += (return_sample - value) / count
```
这段更新等价于维护所有回报样本的算术平均。
常数步长版本把 /count 替换成 alpha。
## 离策略与重要性采样
- 离策略学习用行为策略 μ 产生数据，却想评价目标策略 π。
- 若 μ 在某动作上概率为 0，而 π 需要该动作，重要性比率无法修正。
- 轨迹重要性比率是每步 π(a|s)/μ(a|s) 的乘积。
- 普通重要性采样无偏但方差可能极高。
- 加权重要性采样通常方差较低，但会引入有限样本偏差。
- 长轨迹会让比率乘积剧烈放大或缩小。
- 实际使用时常结合截断、加权或 doubly robust 方法。
- 覆盖性假设是离策略评估的底线。
## 常见误区
- 把 MC 更新放在每一步后立即执行，却仍声称目标是完整回报。
- 在 continuing 任务中没有截断或折扣处理，就直接套用 episodic MC。
- 只采样当前贪心动作，导致其他动作价值永远无法估计。
- 把高方差样本均值的波动误认为真实策略大幅变化。

# 第5章 时序差分：TD、SARSA 与 Q-learning
## 本章定位
- 时序差分学习结合了 MC 的采样和 DP 的自举。
- 它不需要环境模型，也不必等到 episode 结束。
- TD 目标使用一步奖励加下一状态的当前价值估计。
- SARSA 和 Q-learning 都学习动作价值，但处理下一动作的方式不同。
- 本章重点是 TD 误差、on-policy 与 off-policy 的控制差别。
- 理解这些更新是进入深度 Q 网络和 actor-critic 的基础。
## 更新速查表
| 方法 | 目标 | 策略关系 |
|---|---|---|
| TD(0) | R+γV(S') | 评价固定策略 |
| SARSA | R+γQ(S',A') | on-policy 控制 |
| Q-learning | R+γmax_a Q(S',a) | off-policy 控制 |
| Expected SARSA | R+γΣ_aπ(a|S')Q(S',a) | 可 on-policy 或 off-policy |
## TD 预测
- TD(0) 更新 V(S_t) 朝向 R_{t+1}+γV(S_{t+1})。
- TD 误差 δ=R_{t+1}+γV(S_{t+1})-V(S_t)。
- 更新幅度由步长 α 控制，α 太大可能振荡。
- 自举让 TD 可以在线更新，但也会引入估计偏差。
- 与 MC 相比，TD 通常方差较低，因为目标只看一步随机奖励和一个估计。
- 终止下一状态的价值通常取 0。
- TD 可用于 continuing 任务，因为不需要等待终局。
- 多步 TD 在 MC 和一步 TD 之间折中。
## SARSA
- SARSA 名称来自 S,A,R,S',A' 五元组。
- 它的目标使用实际下一动作 A' 的 Q 值。
- 若行为策略是 epsilon-greedy，SARSA 学到的是包含探索影响的价值。
- 因此在有风险区域时，SARSA 可能学到更保守路径。
- SARSA 是 on-policy，因为更新目标跟当前实际行为策略一致。
- 改进策略时通常仍保持 epsilon-greedy 探索。
- 若 epsilon 逐渐趋近 0，最终策略可趋向贪心。
- SARSA 的安全性优势来自它把探索动作的后果算入价值。
## Q-learning
- Q-learning 的目标使用下一状态的最大动作价值。
- 它学习贪心目标策略的价值，即使行为策略仍在探索。
- 这使它成为典型 off-policy 控制算法。
- max 操作可能带来过估计偏差，尤其在噪声估计下。
- 行为策略仍必须充分探索，否则许多状态动作对没有数据。
- 表格型收敛结论依赖合适步长、充分访问和有限 MDP 条件。
- 函数近似下，Q-learning 可能不稳定。
- Double Q-learning 用解耦选择和评价来缓解过估计。
## 常见误区
- 把 SARSA 写成 max 目标，混成了 Q-learning。
- 说 Q-learning 不需要探索；它的目标 off-policy，但数据仍需覆盖。
- 忘记终止状态下一步价值为 0。
- 把 TD 误差正负号写反，导致更新远离目标。
- 用过大 α 让新样本完全覆盖历史，训练曲线剧烈震荡。
- 把单次 TD 误差大理解为策略一定差，而可能只是奖励噪声。
- 忽略行为策略与目标策略差异，导致离线数据使用不当。

# 第6章 函数近似与 DQN
## 本章定位
- 表格方法为每个状态动作保存一个数，面对大状态空间会失效。
- 函数近似用参数化模型把相似状态的经验泛化到未见状态。
- 线性特征、树模型和神经网络都可以近似价值或策略。
- 深度 Q 网络把 Q-learning 目标和神经网络拟合结合起来。
- 函数近似提高表达能力，也带来稳定性和泛化风险。
- 本章重点是特征、损失、经验回放、目标网络和过估计。
## 函数近似基础
- 近似器写作 Q(s,a;w) 或 V(s;w)，w 是可学习参数。
- 线性近似常写成 Q(s,a;w)=w^T x(s,a)。
- 特征 x 决定哪些状态动作被认为相似。
- 好的泛化能减少样本需求，坏的泛化会把错误传播到许多状态。
- 训练目标常是让预测值接近 TD 目标。
- 梯度下降只保证降低当前样本损失，不保证策略立刻变好。
- 输入归一化和奖励尺度会影响优化稳定性。
- 分布漂移是常态，因为策略更新后访问状态会改变。
## DQN 组件
- DQN 用神经网络输出每个离散动作的 Q 值。
- 经验回放是 DQN 系列常用稳定化组件，不代表所有深度强化学习方法都需要回放。
- 经验回放把转移样本存入缓冲区，训练时随机抽取小批量。
- 随机抽样降低连续样本相关性，提高数据复用。
- 目标网络是主网络的延迟副本，用于计算 TD 目标。
- 延迟更新目标网络能降低目标追着预测同时移动的程度。
- 损失常用 (y-Q(s,a;w))^2 或 Huber 损失。
- 行为策略常用 epsilon-greedy 从 Q 网络导出。
- 目标 y=r+γmax_a Q_target(s',a) 在终止时去掉未来项。
## 小批量训练形状
```python
# pseudocode: actions shape [batch], network output shape [batch, action_count]
q_all = online_net(states)
q = q_all.gather(dim=1, index=actions[:, None]).squeeze(1)
next_q = target_net(next_states).max(dim=1).values
target = rewards + gamma * next_q * (~terminated)
loss = huber(q, target.detach())
```
detach 表示目标值不应通过目标网络反向传播到当前更新。
实际代码要区分 terminated 与 time-limit truncation；真实终止清零未来项，时间限制截断通常应按任务是否继续来处理。
## 稳定性风险
- 函数近似、自举和 off-policy 结合被称为 deadly triad。
- 三者同时出现时，价值估计可能发散或剧烈震荡。
- 经验回放缓解相关样本问题，但不会消除所有 off-policy 风险。
- 目标网络减慢目标变化，但目标仍来自估计而非真值。
- max 操作会偏向高估带噪声的动作价值。
- Double DQN 用在线网络选动作、目标网络评价动作，以缓解高估。
- 优先经验回放改变采样分布，需要重要性权重修正偏差。
- 监控 Q 值范围比只看奖励曲线更容易发现发散。
## 工程判断
- 如果动作空间连续，普通 DQN 的枚举 max 不再直接适用。
- 高维像素输入需要足够数据和合适网络结构。
- 离线数据训练 DQN 时，分布外动作的 Q 值可能被严重高估。
- 奖励裁剪能稳定训练，但会改变不同奖励幅度的意义。
- 目标网络更新频率过快会降低稳定化效果，过慢会让目标陈旧。
- 回放缓冲太小会遗忘多样经验，太大可能含大量过时策略数据。
- 评估时应关闭探索或单独报告探索策略表现。
- 多随机种子是深度 RL 报告中的基本要求。

# 第7章 策略梯度与 Actor-Critic
## 本章定位
- 价值方法先估计动作价值，再从价值中导出策略。
- 策略梯度方法直接优化参数化策略 π_θ(a|s)。
- 直接优化适合连续动作、随机策略和需要可微概率的场景。
- REINFORCE 用采样回报乘以 log 概率梯度构成无偏估计。
- baseline 和 advantage 主要用于降低方差。
- Actor-Critic 用 actor 表示策略，用 critic 估计价值或 advantage。
## 策略目标
- 本章为推导 REINFORCE 默认有限期、γ=1 的未折扣回报目标 J(θ)。
- 若改用折扣初始状态目标，常见推导需要在每步梯度项外保留 γ^t，或明确说明使用了等价目标。
- 策略参数 θ 改变动作概率，进而改变轨迹分布。
- score function 技巧把轨迹概率的梯度写成 ∇θ log π_θ(a|s)。
- REINFORCE 更新方向与 G_t ∇θ log π_θ(A_t|S_t) 成正比。
- 若采样动作带来高回报，就增加该动作在该状态下的概率。
- 若回报低于基线，更新会降低相应动作概率。
- 随机策略保留探索，也能表达多峰行为。
- 连续动作中，策略可输出高斯分布的均值和方差。
## baseline 与 advantage
- baseline b(s) 不依赖当前动作时，不改变策略梯度期望。
- 这里的“不依赖当前动作”指在给定状态条件下不随本次采样动作改变。
- 常用 baseline 是状态价值 V_pi(s)。
- Advantage A(s,a)=Q(s,a)-V(s) 衡量动作相对平均水平的好坏。
- 使用 G_t-V(S_t) 可作为 sampled advantage。
- 好的 baseline 能显著降低方差。
- baseline 若依赖动作，可能引入偏差。
- 优势估计本身也可能有偏差方差折中。
- GAE 用 λ 在多步估计之间折中，但本章只需掌握直觉。
## Actor-Critic
- actor 是策略网络，负责产生动作分布。
- critic 是价值网络，负责估计 V、Q 或 advantage。
- critic 提供低方差学习信号，使 actor 不必等待完整回报。
- 若 critic 估计有偏，actor 更新也可能被带偏。
- 常见 critic 回归目标是 TD return 或多步 bootstrapped return；TD 误差是预测值与目标的差。
- actor 更新常用 advantage 乘以 log 概率梯度。
- 熵奖励可鼓励策略保持探索。
- 训练时要平衡 actor、critic 和 entropy 的损失权重。
## 策略梯度小表
| 项 | 直觉 |
|---|---|
| log π(a|s) | 当前策略给已采样动作的对数概率 |
| advantage | 这个动作比平均选择好多少 |
| entropy | 策略分布的随机性 |
| baseline | 降低方差的参照值 |
表中各项经常同时出现在 actor 的损失函数中。
## 常见误区
- 把回报直接对动作求导；采样动作不可导时要用 log 概率技巧。
- 认为 baseline 会改变最优策略；合格 baseline 只降低方差。
- 把 advantage 为正理解成奖励必为正；它只是相对基线更好。
- critic 越复杂越好；过拟合 critic 会给 actor 错误信号。
- 忽略动作概率裁剪或正则，导致策略一步变化过大。
- 只报告 actor loss，而不报告回报和熵。
- 在连续动作中忘记动作缩放和边界处理。

# 第8章 探索、评估与奖励安全
## 本章定位
- 算法能学到什么，首先受它探索到什么限制。
- 探索是在短期收益和信息获取之间做取舍。
- 评估要回答策略是否真的变好，而不是训练曲线是否好看。
- 奖励安全关注智能体是否优化了代理目标却伤害真实目标。
- 本章把探索、离策略评估、实验报告和 reward hacking 放在同一张检查表中。
- 最终目标是让强化学习结果可信、可复现、可部署前审查。
## 探索策略
- epsilon-greedy 用小概率随机动作保持覆盖。
- softmax 探索按价值差异分配概率，温度越高越随机。
- UCB 用均值加不确定性奖励鼓励尝试少选动作。
- Thompson sampling 从后验采样模型或价值，按样本最优行动。
- 内在奖励可鼓励新状态、预测误差或信息增益。
- 探索奖励若设计不当，会让智能体追求新奇而忘记任务。
- 安全任务中需要限制探索动作，不能把危险行为交给随机试错。
- 探索调度应和训练阶段、环境风险及评估协议分开描述。
## 评估原则
- 训练回报不是最终证据，因为它混合了探索、调参和环境随机性。
- 评估策略应固定，常用无探索或指定探索率的策略。
- 要在未用于调参的随机种子、关卡或用户切分上评估。
- 报告均值时也要报告方差、标准误或置信区间。
- 样本效率、最终性能和稳定性是不同指标。
- 离线评估需要行为策略概率或可信的反事实估计。
- 若目标策略会选择日志中没有覆盖的动作，离策略评估不可靠。
- 部署前应做压力测试和失败案例分析。
## 评估报告模板
| 项目 | 应报告内容 |
|---|---|
| 环境 | 版本、终止条件、奖励定义 |
| 训练 | 步数、种子、探索、超参数 |
| 评估 | episode 数、策略模式、置信区间 |
| 安全 | 约束、失败案例、人工复核 |
表格的目的不是形式化，而是让结果能被别人复查。
## 奖励安全
- reward hacking 是智能体利用奖励漏洞取得高分却违背真实意图。
- 代理指标越窄，越容易被策略钻空子。
- 奖励塑形要检查是否改变最优策略或诱导副作用。
- 约束可把不可接受行为从奖励权衡中拿出来。
- 人类反馈能补充目标信息，但也会带来标注偏差和一致性问题。
- 监控指标应包含真实业务目标、安全事件和分布外行为。
- 部署后环境会变化，奖励和策略都需要持续审查。
- 安全评审应包括“如果智能体只最大化这个数，会做什么”。
## 离策略评估
- 离策略评估用旧策略数据估计新策略表现。
- 核心难点是新策略可能选择日志很少见的动作。
- 重要性采样要求知道或估计行为策略概率。
- 模型式 OPE 依赖学到的环境模型，模型偏差会影响结论。
- Doubly robust 结合模型估计和重要性修正，目标是降低单一路径风险。
- 支持集不重叠时，没有统计技巧能凭空恢复未观察动作后果。
- OPE 结果应给出不确定性，而不是单个确定分数。
- 高风险场景应逐步上线，并配合人工或规则保护。
## 复习清单
- 能比较 epsilon-greedy、softmax 和 UCB。
- 能解释为什么评估要和训练探索分开。
- 能计算简单 epsilon-greedy 概率。
- 能说明离策略评估的覆盖性要求。
- 能识别 reward hacking 的典型症状。
- 能设计包含置信区间的实验报告。
- 能把奖励塑形和安全约束区分开。
- 能提出部署前的失败案例检查。
