# v0.15.11 — `/openapi.json` 的版本号不再抄第二份字面量

> 日期：2026-08-22。审查 Agent `reviewer-facts` 复验时给的判断，我独立复核后采纳。

## 病在哪

`pen/app.py:57` 是 `FastAPI(title="Socratic Pen", version="0.12.13", …)`，
而 `pen/__init__.py:3` / `manifest.json:4` / `package.json:4` / `pyproject.toml:7`
**四家都是 `0.13.1`**。四对一，落单那个是抄的第二份字面量。

我一直没改，因为不确定这是不是「sidecar 有自己的版本节奏」。审查查过了，我复核属实：

- **全仓没有任何代码读它。** `grep` 过 `pen/` `src/` `scripts/`，除了 `:57` 那一行定义之外零引用；`pen/tests/` 里也没有断言碰它
- 它唯一的出口是 `/openapi.json` 的 `info.version`

所以它不是有意的独立编号，就是一个忘了改的字面量。**没人读的常量必然过期**——
它漂了三个版本没人发现，正是这条规律。

## 改法

`version=__version__`，从 `pen/__init__.py` 读。不是把 `0.12.13` 手改成 `0.13.1`——
那只是把下一次漂移推迟到下一次发版。

**并且补上那个「读它的人」**：两条测试。
- `app.version == pen.__version__` ——两仓都跑
- `pen.__version__ == manifest.json["version"]` ——用 `pytest.skip` 而不是裸 `return`：
  实验室仓的插件在 `obsidian/` 下，根目录没有 `manifest.json`，那边跳过是对的，
  但要在报告里**留个痕**，否则「静默不跑」和「跑过了」长得一模一样
  （这个写法是审查在别处提过的建议，这里一并用上）

README「还欠着的」里那一条同步删掉（中英）。
