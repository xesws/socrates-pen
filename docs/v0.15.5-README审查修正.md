## 最要命的一条：五张 SVG 在一种常见配置下整张空白

`docs/img/*.drawio.svg` 五张图**都定义了 `.dg-bg{fill:none}`，但没有任何元素用这个 class**——
也就是根本没画背景层。而深色配色走的是 SVG 内部的
`@media (prefers-color-scheme: dark)`，把 `text{fill:#e6edf3}` 设成近白。

**这条媒体查询跟的是操作系统外观，不是 GitHub 的主题开关。** 于是：

| 系统外观 | GitHub 主题 | 结果 |
| --- | --- | --- |
| 浅色 | 浅色 | 正常 |
| 深色 | 深色 | 正常 |
| **深色** | **浅色** | **近白文字铺在白页上 —— 整张图空白** |

第三行不是边缘情况：macOS 用深色外观、GitHub 主题钉成 Light 的人很多。

**我之前"验过图"是假的。** 我在 Chrome 里开的是自己写的预览页，页面背景**跟着系统主题走**，
所以那个错配组合我一次都没撞到。

### 改法与这次的真验证

给每张图在 `</style>` 后、`<defs>` 前插一块不透明背景，并让它跟着配色翻：

```svg
<rect class="dg-bg" x="0" y="0" width="100%" height="100%"/>
```
```css
.dg-bg{fill:#ffffff}
@media (prefers-color-scheme: dark){ .dg-bg{fill:#0d1117} }
```

这次真去复现了那个失败组合：写一个**背景死钉 `#ffffff`、不跟随系统**的测试页，
用 DevTools 强制 `prefers-color-scheme: dark`，截图确认——修之前是空白，
修之后是深色图块配白字，可读。反向组合（系统浅色）也截了，白底深字，与页面融为一体。

最坏情况从「图是空白的」降级成「白页上一块深色图」——难看，但看得见。
