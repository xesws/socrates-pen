# v0.15.17 — README 顶部的肖像改成截图

> 日期：2026-08-21。插件 semver 不动（仍 0.13.1），`src/` `pen/` `styles.css` 一行不改，不发 Release。

## 病在哪

README 顶部那幅 ASCII 肖像（`PORTRAIT_WIDE`，51 行 × 76 列）裸放在一对三反引号里。读者的原话是
「非常窄，感觉整个被压缩了一样」。

根因不在画，在行高。这幅画是按 `line-height: 1` 画的——生产 CSS `styles.css:571` 起的
`.socrates-pen .sp-art` 明写 `line-height: 1`。GitHub 代码块的行高约 1.45，于是：

| | 宽 | 高 | 比 |
| --- | --- | --- | --- |
| 设计意图（line-height 1） | 76 × 0.602 = 45.8em | 51em | 0.90 |
| GitHub 实际（line-height 1.45） | 45.8em | 74em | 0.62 |

纵向被拉长 45%。**按生产 CSS 渲染成 HTML 再截图，比例自然就回来了。**

顺带治另一个病：读者要滚过 97 行（两块围栏 + 一个无父 H2 的孤立 H3 + 四枚徽章 + 三行引言 + 七项目录）
才看到第一个 `##`。

## 做什么

1. 新增 `scripts/render-hero.py`：从 `src/logo.ts` 取画 → Chromium 按 `line-height: 1` 排版 → 截图 → Pillow 量化
2. 产出 `docs/img/hero.png`（第一张进仓的位图；此前 `docs/img/` 只有 5 张 `.drawio.svg`）
3. 中英两份 README 顶部各 96 行换成一个 `<img>`

## 关键决策

**横排卡片，用 `PORTRAIT_NARROW`(31×46) 而不是 `PORTRAIT_WIDE`(51×76)。**

竖排先否决：WIDE 竖排在 16px 下是 732×816，卡片总高 900+，比现在还占地方。

横排之后卡片高度成了硬约束（≤ 410px，扣掉 padding 后肖像 ≤ 341px），**行数决定字号上限**：

| 资产 | 行数 | 可用字号 | 每列宽 | 结果 |
| --- | ---: | ---: | ---: | --- |
| `PORTRAIT_WIDE` | 51 | 341/51 = 6.7px | 4.0px | 糊成灰泥 |
| `PORTRAIT_NARROW` | 31 | 341/31 = 11px | 6.6px | 字符各是各的形状 |

反直觉但对：同一显示宽度下 NARROW 每像素信息**更多**——WIDE 挤进 305px 是 4.0px/列，
NARROW 是 6.6px/列，多出来的 30 列全被降采样吃掉。

**字标最后没用 `logo.ts` 里的 ASCII 字标，改成了真文字。** 设计阶段我判断「字标同理选 NARROW」，
实测推翻了：ASCII 密度画的形状信息编码在字符的**密度差异**里，单个字符必须能被分辨，整幅画
的形状才立得住。横排右栏只有 424px，四种都试过——

| 方案 | 每列 | 结果 |
| --- | ---: | --- |
| `WORDMARK_NARROW` @11px | 6.6px | 认不出字母 |
| `WORDMARK_NARROW` @12px | 7.2px | 勉强，仍认不出 |
| `WORDMARK_WIDE` @8.8px | 5.3px | 更糟——格子多 25%，但每格都糊了 |
| `WORDMARK_WIDE` @16px | 9.6px | 清楚，但要 674px 宽，横排给不起 |

竖排也试了：肖像宽高比 0.9（接近正方形），要够宽就必然够高，卡片长到 580px 且左右大片留白。
横排是唯一能把 hero 压在 411px 的布局，而在 840px 宽里「清晰肖像 + 清晰 ASCII 字标」装不下——
肖像要 ~280px、字标要 ~570px，加间距超出可用的 770px 约 100px。

一个认不出字母的字标就是一片噪点，不如换成读得出来的字。这跟 `src/views/splash.ts:74` 的判断
同源——那里写着「字符画只用在肖像和字标上……标语是"字"，让它保持可读」；在 README 这个尺寸下，
字标也落进了「必须可读」那一边。肖像仍是字符画，密度阶那一行也照旧展示画它用的那套字符。

## 图里放什么

**hero.png 里没有一个汉字、没有一句英文——中英两版共用同一个文件。**

进图：肖像（字符画）、SOCRATES 标题（文字）、副题 `Socrates-agent`（`i18n/zh.ts:169` 与 `en.ts:129` 逐字相同，语言中立）、
密度阶 `. : s A 3 G & @`（`logo.ts:4` 的口径是「8 级密度阶」）。

留 markdown：标语（中英文案不同，进图就要出两张）、四枚徽章（图里的徽章不可点、不随版本更新）、
语言切换（必须可点）。

这个划分不是新发明的，是产品自己的既有原则——`src/views/splash.ts:74`：
「字符画只用在肖像和字标上——那两个是"图"，标语是"字"，让它保持可读、可选、可被读屏正常念出来」。

## 两个容易踩的坑

**一、必须钉死 Menlo。** 本机没有 SFMono.otf，`ui-monospace` 会落到 `.SF NS Mono`（字宽比 0.618164），
和 Menlo（0.602051）差 2.6%，卡片宽度会在 840 和 862 之间漂。脚本在页内做两级断言：先拿 serif 当对照
查 Menlo 是否真在（只查字宽比不够——Courier 是 0.6001，差 0.2%，会蒙混过关），再查字宽比。
**对不上直接退出**，绝不静默出一张比例不对的图——那正是当初这幅画被压扁却没人发现的原因。

**二、量化必须用 MAXCOVERAGE，不能用 MEDIANCUT。** Skia 给渐变加有序抖动防色带，这层噪声把 PNG
从 164 KB 撑到 415 KB。MEDIANCUT 按像素**数量**分配色槽，会把槽全喂给噪声，渐变本身只剩几档，
最大误差 35/255，**真的出色带**。MAXCOVERAGE 按色彩空间**覆盖**分配，保住渐变那条 65 色斜线，
顺手把噪声吸回真值：61 KB，最大误差 3/255。

**三、`quantize(colors=N)` 的调色板只有 N 项，索引 N 落在数组外。** 想拿索引 192 当透明色，
必须先 `putpalette` 把调色板撑到 193 项——否则 `save(transparency=192)` 写出的 tRNS 只有 192
字节，第 192 项越界，**圆角会变成不透明的黑**。这个 bug 实际出过一次图才被验证脚本抓到：
四角索引确实是 192，但 `convert("RGBA")` 读出来 alpha=255。验证要查的是合成后的 alpha，
不是索引值。
