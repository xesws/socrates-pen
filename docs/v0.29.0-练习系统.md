# 练习系统（开发中，尚未发布）

从教材的 Meta Questions 建立题库和知识点图，完成练习、rubric 评分、正式作答分析与个性化推荐。此功能默认关闭。

## 使用

1. 在 Socrates 设置中开启实验练习，打开教材，再运行打开练习的命令。
2. 在资源页生成题库。生成与独立审查使用设置中的主模型；页面显示进度、问题和 token 用量，可以停止及继续。
3. 调整测验范围、知识点权重、目标分数、日期与每天练习分钟数。
4. 选择普通练习、领取推荐或开始测验。单选、填空和简答均可逐题完成，草稿及会话会保存。
5. 练习提交后查看评分；测验交卷后查看评分。失败的评分可重试；失败不记为零分。
6. 在分析页查看各知识点的正式作答证据、预测得分、薄弱方向和当前模型状态。

新 H1/H2/H3 格式按已有原题一对一导入，模型仅补充知识点与 rubric。数量参数适用于显式生成新变体及旧格式生成路径；该路径默认每道 MQ 六道练习题和三组预留测验题。预留题不用于普通练习。生成新一批题目会再次调用模型，未通过校验的内容不用于作答。

## 教材格式与资源范围

新格式使用 H1 单元、单元最后的 H2 `meta question`，以及每题的 H3 标题。题内 H4 固定为题型、题干、选项、答案和解答；详见 [Schema](mq-schema-v1.md) 与 [测试教材](../evals/mq_v1/book.md)。旧版八拍 `**Q1. 问题标题**` 教材保留原解析路径。

模型只接收 MQ 块与其中的参考答案，不读取正文、不跟随回读链接。知识点、关系及评分标准的引用必须对应 MQ 原文。知识图覆盖的是 MQ 考查范围。

资源原文、题目、评分标准均保留版本。教材 MQ 变化后，新会话要求重新构建；已经开始的会话继续使用冻结的题目。缺少某个知识点的合格题时，界面报告覆盖缺口，不把不完整测验当成完整达标证据。

## 评分与分析

单选及有明确答案的填空采用规则评分；语义填空、简答通过固定 rubric 逐项评分。每项关联一个知识点，后端计算总分并检查分数范围、评分项集合和回答证据。

首版展示评分依据，未提供人工改分或评分申诉。[旧测评](../evals/mq_v1/REPORT.md) 保留历史失败；视觉需求已更正为用户上传作答图片，见 [作答图片测评](../evals/answer_images_v2/REPORT.md)。最新 [80题教材测评](../evals/rl_textbook_v1/REPORT.md) 中，原题完整导入、rubric 恢复后全部通过复核；96 次开放评分有 1 次多给 10 分。

新分析只消费成功评分的正式作答。聊天画像保持独立。未测、证据不足和薄弱分别展示。目标默认 80 分、每日 20 分钟；稳定达标要求同一蓝图下三个不同预留题测验均达标、至少相隔 24 小时、分差不超过设定值（默认 10 分）。

分析模型采用正则化 fractional logistic regression，调度模型采用 contextual reward regression。训练、验证、版本保存与回退均在本地运行。个人数据不足时显示冷启动状态；通过时间留出验证后才启用训练模型。开启功能不会立即产生已经训练好的个性化模型。

推荐仅在用户领取时交付，包含约 10% 的候选探索。记录候选集、选择概率、推荐前状态和后续预留测验结果；缺失后续结果不当成零奖励。预测分数和实际测验成绩分别显示，离线策略评估不能直接证明真实学习收益。

## 运行与数据

Obsidian 继续连接现有 sidecar。该进程持有题库和作答数据，按需启动两个独立的本地进程：Analysis 与 Scheduling。子服务使用动态 loopback 端口和内部认证，拥有各自 SQLite 数据库，不直接访问其他服务的文件。

数据保存在 `PEN_DIR/practice/`：源码环境通常是仓库的 `.pen/practice/`，安装环境通常是 `~/.socrates-pen/practice/`。数据库按 vault 隔离；练习记录不进入会话保留期清理，也不写回教材。

作答状态与评分事件原子提交。重复提交不产生第二次作答；子服务重启后通过事件序号补处理。主服务退出后子服务退出；默认保活行为沿用现有 sidecar 设置。

## 验证

```bash
python -m pytest pen/tests -q
npm run build
python scripts/check-practice-ui.py /tmp/socrates-practice-ui
python scripts/check-practice-live.py /tmp/socrates-practice-live
```

测试使用隔离的临时 vault、模拟模型和真实本地子进程，不调用用户配置的模型。前端浏览器检查需要可选的 Python Playwright 与 Chrome/Chromium；真实 HTTP 联动检查还需要本地 5173 或 4173 端口空闲。

最新验证：Python 全量 1224 项通过；插件构建、离线页面交互与真实网关/子服务的浏览器联动已验证。强化学习教材批量测评使用 189 次真实调用、1,923,816 tokens，保留原始记录。新题变体生成质量与长期学习收益尚未实测。
