# v0.21.1 — 写回纪律合成一份

> 日期：2026-09-02。承 `v0.21.0` 留下的那笔旧账。

`v0.21.0` 的设计笔记末尾写着「**下一版必须有人来把这两句话对齐**」。这就是那一版。

## 病灶

同一条规矩（写回时先读后改）在仓库里有**三处**措辞，其中一处说反了：

| 位置 | 说的是 |
|---|---|
| `pen/session.py` 的 `SYSTEM_PROMPT_TEMPLATE` | 「拿到返回之后接着 edit_file，**同一轮里做完**」 |
| `edit_file` 的工具描述（`pen/agent/registry.py`） | 同上，且明写「不能**同一批**」 |
| `pen/chips.py` 的 `CHIP_INTENT["writeback"]` | 「**下一轮**再单独 edit_file」 ← 说反了 |

「下一轮」是我们自己写错的一句话。真实约束从来只是「拿到 `read_file` 的返回之后再改」——
模型逐字照做就会回一句「下一轮我就动手」然后停在那儿，读者得再说一遍、再花一轮钱。
`pen/tests/test_agent.py` 的 `test_read_then_edit_in_one_turn_is_allowed` 早就钉住了
「同一轮读完接着改必须走得通」。

有意思的是**这次清理是第二次**：之前那一轮已经把这句错话从 `SYSTEM_PROMPT` 和工具描述里
拿掉了，还配了 `test_the_prompts_no_longer_say_next_round` 盯着——但那条闸**只看那两处**，
于是 `CHIP_INTENT["writeback"]` 里的第三份原样活了下来，而且它是每一次写回轮都会被注进
`[意图]` 段的那一份。**闸没覆盖到的地方，等于没清。**

`v0.21.0` 做自定义泡泡时撞上了它：三个预置模板全是写回类，等于让新功能的默认路径去踩这条
已知的矛盾。当时的处理是绕开——另写一份 `WRITEBACK_DISCIPLINE` 对齐 `SYSTEM_PROMPT`，
旧的那条不动，留一条回归闸盯着它的措辞，把账记下。于是短期内变成了**两份**。

## 改法

把「怎么写」抽成唯一定义点，两个调用方各自只管「写什么」：

```python
WRITEBACK_DISCIPLINE = {...}          # 只放机制，不放开场白

CHIP_INTENT["writeback"]["zh"] = "把刚才的解答写进手册。" + WRITEBACK_DISCIPLINE["zh"]
# custom_intent()：读者写的那段 + "上面这件事会改写手册原文。" + WRITEBACK_DISCIPLINE
```

开场白**不放进纪律**：固定芯片说「把刚才的解答写进手册」，自定义泡泡说「上面这件事会改写
手册原文」，两边各说各的。混进去的话固定芯片那条会读成
「把刚才的解答写进手册。这枚芯片会改写手册原文。」——同一件事说两遍。

**「同一轮」不等于「同一批」。** 放宽的只是「不用等下一轮」；同批发出时模型还没看到原文，
`old_string` 只能靠猜，那条仍由 `pen/agent/permissions.py` 的 `read_first_block` 硬闸拦着
（`test_same_batch_read_and_edit_is_still_blocked`）。措辞里「看到它返回的带行号原文之后再
edit_file」说的正是这件事，别改松。

## 闸

- `test_chips.py` 那条回归闸**从「盯着债还在」翻成「盯着它别回来」**：断言
  `CHIP_INTENT["writeback"]` 和 `custom_intent()` 都整段取自同一份 `WRITEBACK_DISCIPLINE`，
  三处措辞一致。
- 新增一条钉住「同一轮 ≠ 同一批」，防止下次有人为了「更顺」把措辞改松。
- `test_agent.py` 的 `test_the_prompts_no_longer_say_next_round` **扫全表**，不再只看两处——
  这条闸上次漏掉第三处，正是这笔账能活这么久的原因。
