# 已有 MQ 题目导入格式 v1

H1 为单元；有题单元最后一个 H2 必须为 `meta question`（忽略大小写）。其中 H3 为题目标题。无该小节的单元直接跳过；重复或非末尾 MQ 报格式错误。只识别 Markdown AST 的顶层标题，代码和引用内的标题不参与划界。

每题用 H4 标记「题型、题干、选项、答案、解答」。题型使用 `single_choice`、`fill_blank`、`short_answer`，也接受「单选、填空、简答」。题干与解答可使用代码、公式、Mermaid 和本地 PNG/JPEG/WebP/GIF 图片。

单选的选项用 H5 `A`、`B` 等标记，答案填写一个选项 ID。填空在题干使用 `{{b1}}`；答案为单个 JSON 围栏，例如：

```json
{"b1":{"grading":"exact","answers":["3"],"case_sensitive":false}}
```

`grading` 可为 exact 或 semantic；一题中的各空使用同一模式。数值近似需同时声明 numeric_value 与非负 numeric_tolerance。简答的答案区直接写参考答案 Markdown。

脚本导出每道题的题型、原题干、原选项、答案、解答、原题块、来源行号、字段范围以及附件清单。正文不会送入题目模型。图片使用相对路径，保存 SHA-256；图片字节变化会改变题目版本。

当前安全边界为教材同目录及子目录内的本地图片；缺失、越界或远程引用会报问题。支持标准 Markdown 图片与 Obsidian `![[...]]`；不会把代码中的示例图片语法当成图片加载。

新格式默认构建路径一对一导入题目，并让模型补充知识点和 rubric；数量参数仅用于显式生成新变体。旧版八拍 `**Q1. ...**` 教材保留原有解析路径。

示例和实测见 [固定教材](../evals/mq_v1/book.md)、[测评报告](../evals/mq_v1/REPORT.md)。

## 递进 rubric 与用户答案图片

教材标题/题干/答案格式保持上述规则。导入原题后生成评分标准时，会发送 [10 个完整面试题示范](interview-rubric-examples.md)，包括每题 8 个评分项，以及基础 20 分、进阶累计 50 分、完整 100 分的作答示范。

复杂面试题使用 `rubric_schema: "tiered-v1"`。每个 criterion 包含 `tier`、明确数值的 `levels: [{id, score, condition}]`；`rubric_levels` 按 basic/advanced/complete 列出累计必需的 criterion IDs 和对应满分总和。程序校验档位、累计关系及总分。模型选择 `level_id`，程序映射为分值并加总。等级要求其全部评分项达到满分；独立评分项仍可单独得分。简单事实题/填空题不硬凑三个知识层次，但同样需要明确得分档位。旧题库的旧 rubric 继续可读，重建后使用新契约。

解答题与填空题的作答对象支持 `images: [{mime, data}]`，`data` 为 base64；文字可留空。选择题不接受作答图片。图片上传/粘贴、预览、删除、草稿恢复和最终提交均已接入练习页；需在插件设置中开启图像理解并配置支持图片的模型。每次最多 4 张，每张最多 2 MB。

评分时一次请求直接发送题目、参考答案、rubric、可选文字及学生上传图片。不会把选择题转换成解答题，也不会把教材图表当成学生作答。返回逐项判定与图片内容识别记录，供用户核对；识别记录不是独立 OCR 真值。无法辨认时返回 `insufficient_evidence`，保留作答并标为评分失败/需复核，不给零分、不发知识掌握事件。现有重试按钮使用原提交重新评分；需要更换图片时可在新练习中重做。

实测：[作答图片与递进 rubric 的闭环报告](../evals/answer_images_v2/REPORT.md)。
