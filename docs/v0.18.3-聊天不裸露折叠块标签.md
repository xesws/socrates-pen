# v0.18.3 — 聊天界面不再裸露 details 折叠块标签

> 日期：2026-08-23。用户实测报告：「先别揭晓，问我一个问题」的回复区偶尔
> 暴露一个 "details" 字样，之后再看又正常。grok-4.6（xhigh）独立审计 + CDP
> 实证定位根因后修复。

## 根因（审计结论，按可能性排序）

1. **流式预览裸显（主因）**：回复流式写入期间，面板用 `setText` 直写原文——
   手册按八拍体例含 `<details>` 折叠块，它们随选区邻域进 prompt，模型偶尔回显
   这些标签；流式期间裸出，`done` 后 `finally` 里的 `paintLog` 用
   MarkdownRenderer 重渲染，又正常了。「时有时无」正源于此。
2. 畸形折叠块（缺 `<summary>`）会渲染成原生部件，浏览器默认标题就是
   "Details"，看起来也像泄漏。
3. 引文条：源码模式划选跨过折叠块时，`textContent` 直写选区原文，持续裸显。

## 改法

新增纯函数模块 `src/foldview.ts`（`scripts/check-fold.mjs` 打包真代码守着，
挂进 `npm test`）：

- `stripFoldTags`：逐标签全剥 + 剪掉流式写到一半的 `<deta` 残尾——用于
  **流式预览**（`paintStreamBubble`）与**引文条展示**（`paintQuote`）。
  发给 sidecar 的 `selected_text` 永远是原文，一字不动。
- `visibleReply`：折叠块标签**只剥独占一行的**，同行 `<summary>文本</summary>`
  解包成纯文本——用于**最终渲染**（`paintLog`）。写回流程散文里的
  `` `<details>` `` 内联代码提及必须活着，判定锚定「独占一行」。
- 系统提示两语各加一行：对话回复不输出 `<details>/<summary>` 或任何 HTML
  标签，折叠块只属于写回手册流程（提示词是软约束，三条硬路径已独立兜住）。

聊天面板不是折叠块的产品面：最终渲染不再生成可折叠部件，内文与摘要文本
直接成正文——折叠体验属于手册里的写回结果。
