## 怎么找到的

sidecar 不落日志文件，编码器的原始回复也不记，面板上只剩一个数字。把放弃的那一批按同样的 prompt
重发给同一个模型（gemini-3.8-flash，thinking low）一枪：10 条全是 `type: META`、`axis: null`，
`evidence_quote` 是「（点了芯片「先别揭晓，问我一个问题」，没打字）」。模型判得对——请求出题不是任何一条
能力的证据。

## 病根

v0.25.0 二审第 7 条：模型没给轴的非 META 编码记一次 attempt 再来，因为**有原话**却不归轴等于永久丢失。
同一版把只点芯片的轮次强制成 ASK（芯片本身就是意图）。两条叠在一起，没打字的轮次走成了：
模型说 META、给不出轴 → 被强制成 ASK → 因为没轴被拒、attempt +1 → 下次同样 → 三次 → 放弃。
每一次都是一枪真实调用，而没有原话就没有更多可找的，结果不会变。

## 改了什么

`pen/profile.py`，仍是唯一定义点：

- `QUIZ_CHIPS = {"socratic"}`：「先别揭晓，问我一个问题」不打字 = 确定性 META（`auto="quiz"`），不送模型。
  真正有信息的是下一轮读者的作答，那轮会以 VERIFY 或 ASK 进来。
- 其他芯片（举例子、零基础讲、自定义）不打字仍送模型归轴：给得出轴就是 ASK；给不出就是 META（`auto="chip"`），
  **不记 attempt**。
- 旧缓存里已经放弃、又没打字的轮次，下次补编码时收成 META；有原话的放弃轮不动（它们是模型真没编出来）。
  读者那 11 条重开面板就收口，不用重算、不花钱。
- 编码器每一枪落一行 `profiles/<id>.coder.jsonl`：轮号、模型、原始回复、解析出几条、编上几条、
  被拒的轮与它们的 attempts；厂商异常也记一行。超过 2 MB 从头写。GET 不写。里面没有钥匙。
