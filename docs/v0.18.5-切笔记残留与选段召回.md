# v0.18.5 — 切笔记残留态清干净 / 无选区命令不再召回旧选段

> 日期：2026-08-23。0.18.4 复测：自动跟随主路径已通；剩三条残留语义。

## 三条残留与修法

1. **切笔记后 chips 还在、草稿还在**——恢复出来的会话自带 5 枚芯片，但没有
   引文时它们是点不动的死按钮（`send` 守卫挡），读者读成「上一条笔记的状态
   没清掉」。修：`paintChips` 两处可见性判据统一为「没引文就藏」
   （`is-off`），划一段捕获后随会话回来；跨笔记重定向同时清输入框草稿
   （打了一半的话属于上一场对话）。
2. **无选中跑 Ask 把上一次的选段「召回」**——`takePick` 的同笔记 `lastPick`
   回退在源码模式下是错的：编辑器选区是状态、失焦不丢，拿不到就是读者真把
   选区收了。回退收窄到**预览模式**（DOM 选区一点面板就塌，缓存才有必要），
   模式从目标笔记自己的 markdown leaf 上读（面板聚焦时
   `getActiveViewOfType` 是 null）。源码模式无选中跑命令 → 「先划一段」Notice。
3. **恢复会话但引文为空时命令静默**——同笔记场景补一条 errNoSelection
   Notice；跨笔记不叠（「已切回…先在笔记里划一段」已经说了）。

## 复审（grok-4.6 xhigh，发版前修毕）

- **ship-blocker**：`paintChips` 末尾既有的 `childElementCount` 翻转会把顶部
  的隐藏翻回来，最终态取决于哪次调用最后发生（竞态式闪烁）——两处判据
  统一为 `!this.quote || childElementCount === 0`。
- takePick 探测点从 active view 改为按路径找 markdown leaf。
- 跨笔记双 Notice 收敛为单条。
- 复审确认与 0.18.1「空会话 5 chip 首屏」诉求无矛盾：那条要求的是**有引文**
  （刚 Use selection）的场景，chips 照旧全展开；这里藏的是**无引文**的死按钮。
