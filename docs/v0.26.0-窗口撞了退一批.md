# v0.26.0 — 窗口撞了退一批：上下文超限的可重试错误 + read_file 分段读

> 日期：2026-09-03。读者要把基座换成千问 3.8 27B（Cerebras，免费版 64k、付费版 128k）。
> 他的担心很具体：压缩机制只管轮与轮之间，一轮之内模型一枪读太多，节点当场 400，这一轮就废了。
> 他要两样东西：把「上下文太长」当成**可重试的错误**连数字一起退回给模型；确认 `read_file` 真能按 offset / limit 分段读。

## 读者看到的

换成小窗口模型之后，问一个要翻几段的问题，状态栏「在翻手册…」跳了几下，然后一条红字：
「节点拒绝了这次请求：This model's maximum context length is 65536 tokens. However, you requested …」。
模型没有机会知道自己读多了，读者也只能重开会话。

## 病根

两道压缩各守一段，中间空着一段：

- `should_auto_compact` 在**轮与轮之间**看上一枪的 `prompt_tokens`，到 32k 折一次。
- `FastWindow` 每一枪发出去之前量一次，但只在 `fast=True` 的快模型路线上跑——它的窗口是写死的常量。

基座路线在**一轮之内**没有任何窗口守卫。基座本来是 1M 窗口，从没暴露过这件事。模型一枪常常吐 7～21 个
`read_file`（每个最多 5000 字符），整批进 `session.messages` 之后下一枪被节点 400，`_agent_loop` 把它当
普通 `rejected` 报给读者。

第二件事是 `read_file` 的截断：按字符硬切，最后一行常常只剩半句，尾巴只写「已截断」，不说停在第几行、
下一段该从哪儿读。`offset` 写成 `"L100"` 会 `ValueError` 一路抛到 SSE，整轮变成「对话中途出了意外错误」。

## 改了什么

**为什么是反应式。** 基座的窗口我们不知道——没有旋钮，也不该猜。节点的 400 是唯一可靠的信号。
撞了之后做的事只有一件：把**这一枪之前那整批工具结果**换成一段带数字的错误，让模型自己改成按行号
区间读。单次 `read_file` 被 `MAX_OUTPUT` 截到 5000 字符，真正撞窗口的从来是一批和一轮的累计，
所以退的单位是「一批」，不是某一条。

`pen/overflow.py`（新）：

- `looks_like_context_overflow`：400 / 413 且报文命中十二个「太长」词之一，或 `code == context_length_exceeded`。
  `max_tokens` 和 `tokens per minute` 不算（那是输出预算填大了、限流）。
- `overflow_numbers`：从报文读「这一枪多少 / 上限多少」。六家节点的形状都试过：OpenAI / DeepSeek / vLLM、
  Cerebras（只报「至少多少」，而且 `you requested 16384 output tokens` 里那个数是输出预算，不能当大小）、
  Google 兼容层、Anthropic 兼容、OpenAI 新文案、Groq 的 413。小于 1000 的数不算窗口。
- `stub_trailing_batch`：从尾巴往前，跳过收口枪塞的那条假 user，收连续的 tool 块，就地换成
  「错误：上一枪被节点拒收——上下文太长（这一枪约 N token，模型上限 M）。这条 read_file 的结果（K 字符，
  第 a–b 行）已经从上下文拿掉。改成分段读：同一路径带 offset 和 limit，一次不超过 80 行……这是本轮第 k/3 次退回」。
  `edit_file` 的结果不退（那是写回记录），退过的不再退。

`pen/tutor.py`：

- 码表加 `PROVIDER_TOO_LONG`，排在视觉判定之前（溢出报文写明 token，视觉那条是在猜）。`ProviderError`
  带 `code / got / limit / estimated`；节点没给数字就用我们的 `est_tokens` 估，并标明是估的。
- `_agent_loop` 加 `_shrink`：撞窗口 → 退这一批重打 → 退不了且是快模型就换基座（现有事件）→ 退不了且是基座
  就真折一次历史（先用 `RollingSummary.plan` 纯预览，估算没变小不折）→ 都不行如实报错。一轮最多
  `OVERFLOW_RETRIES = 3` 次，循环必然终止。工具枪和收口枪两个发枪点都走它，审批续跑同一条路。
- 读者看到的红字换成 `provider.too_long`：写明模型名和节点原话，说清退过、折过，给三条出路。

`pen/readtool.py` / `pen/agent/tools_impl.py` / `pen/agent/registry.py`：

- 截断按**整行**切。还有没读到的行时加尾注：被字符截断写「本次只到第 b 行，文件共 T 行。接着读用 offset=b+1，
  limit 不超过 kept 行」；被 limit 截住写「第 a–b 行，文件共 T 行；接着读 offset=b+1」；读到文件尾不加，
  输出和以前逐字节一致。越界写「文件共 T 行」。尾注没有行号前缀，压缩层的 `_line_span` 照旧认得出区间。
- probe 拿同一个函数取摘录，`resume_hint=False` 关掉尾注。
- `offset` / `limit`：数字串、整数值 float 照收；0 和负数回落默认；`"L100"`、`true`、列表是工具错误
  「必须是正整数」，不再抛。默认 80 行四处（schema、handler、readtool、退回文案）统一读 `READ_LIMIT_DEFAULT`。
- schema 描述和人设各加一句：长文件分段读，截断时按末尾给的 offset 接着读，不要一次读整本书。

体检：窗口小到连体检那一枪都装不下，以前爬完整个减配梯子还是 `rejected`；现在一枪定案叫 `too-long`。

## 闸

## 二审：Codex review 后修的

发版前照老规矩用 Codex（gpt-5.6-sol，xhigh，只读沙箱）审了 `pre-0.26..HEAD` 整段 diff，7 条。
每条先看红再改绿：

- **#1 high · 退回的读没撤销 read-first 资格。** 节点拒了那一枪，模型其实没见过原文，重试只看见 stub，
  却仍能凭 `read_ok` 直接 `edit_file` 进审批。修：`_shrink` 退完把这些路径从 `ctx["read_ok"]` 和
  `session.read_ok_paths` 里拿掉，`read_first_block` 照常拦。
- **#2 · 溢出重试吃掉一格 `max_tool_rounds`。** `continue` 进 `for` 的下一格，轮数小时模型还没机会分段读就被
  推进禁用工具的收口枪。修：工具枪包一层 `while True`，失败的那一枪不占轮数，终止靠 `OVERFLOW_RETRIES`。
- **#3 · 超长单行硬切之后 `kept=1`、不标截断、offset 推到下一行。** 被切掉的半行按行号永远读不到，还声称读完了。
  修：`_cap_lines` 多返回一个 `partial`，尾注如实说「第 N 行本身超过 5000 字符，这里只有它的开头」，不给下一段 offset。
- **#4 · `"²".isdigit()` 为真但 `int()` 抛；几千位数字串也抛。** 修：只认 ASCII 数字，整段包 `except (TypeError,
  ValueError, OverflowError)`；schema 补 `minimum: 1`。0 和负数仍回落默认——模型拿到它要的东西比多一个来回强。
- **#5 · 判定过宽。** 裸 `request too large` 也当溢出——图片把请求体撑爆时节点也这么说，退批、折叠都救不了。
  修：它得同时提到 token 或 context 才算；`input token count` 从词表拿掉（Google 那句已被
  `exceeds the maximum number of tokens` 覆盖）。
- **#6 · 叫 shrink 却可能把上下文撑大。** 两个字的错误结果换成 170 字的 stub。修：stub 不比原文短就不换；
  一批全是短结果时返回空表，走换基座 / 折叠那条路。
- **#7 low · 读者看的 `provider.too_long` 宣称「已退过批、折过历史」**，但体检、画像编码、折叠块生成也用这句。
  修：措辞中性，只说怎么让这一轮装进去的东西少一点。

**没修的半条**：#1 还说「快模型路线就地改 `session.messages` 违反『压缩只作用于副本』」。那条约定守的是
`compact_session` 会把 `session.compacted` 永久置真、丢掉目录 / 邻域 / 书架；退批换的是一段模型**从未见过**
的正文，而且必须留在会话里——只改副本的话下一枪又把同一批大正文发出去，等于没退。基座换回来之后
stub 里写着「再 read_file」，读得回来。

## 三审：第二次 Codex review 后修的

二审的修法再送 Codex 审一遍（同一模型、同一档、只读沙箱）：没有 high，2 条 medium、6 条 low，全修，每条先红后绿：

- **medium · 工具参数是合法 JSON 却不是对象。** `json.loads("null")`、`"[]"`、`"5"` 都过得了
  `JSONDecodeError`，随后 `args.get` 抛——而 assistant 那条 tool_call 已经落进会话，没有配对结果，
  这场会话之后每一枪都 400。修：`_run_tool_batch` 补 `isinstance(args, dict)`，不是对象给一条配对的
  错误结果，接着走。
- **medium · 退批「比原文短」按字符比。** 中文 stub 每 1.5 字一个 token，ASCII 正文每 2.5 字一个：
  134 个 ASCII 字符换成 133 字的中文 stub，字符少了、token 多了。修：用 `est_tokens` 比，不是严格变小就不换。
- **low · 折叠会把溢出 stub 换成通用 drop note**，窗口数字和「分段读」的指令一起丢。修：`_stub_tools`
  认出 stub 原样留着，`dropped` 不计它。
- **low · 排除词压过结构化码。** `code: context_length_exceeded` 的报文附带文字里恰好有 "rate limit"
  就被判成非溢出。修：结构化码先判。
- **low · 报文里几千位的数字串 `int()` 抛**，错误处理路径再抛一次就退化成「意料外的错误」。修：包
  `except ValueError`，跳过试下一个正则。
- **low · `-1` 回落默认而 `"-1"` 报错。** 修：串允许一个前导负号，负数串与负整数同路回落。
- **low · read-first 撤销太粗。** 退掉一条长读把同一路径更早那次真送达过的读的资格也抹了，而 stub 里写的
  正是「前面已经读到的不必重读」。修：历史里仍带行号正文的读所指的路径不撤。
- **low · `provider.too_long` 让读者去敲「/compact」**，插件里没有这条命令；体检、画像那几处也用这句，
  「分段 read_file」对它们不适用。修：措辞改成「主对话里分段 read_file、折叠一次历史或调低自动折叠阈值；
  或换窗口更大的模型」。

pytest **1101 passed**。

## 没做的

- **主动守卫**：从溢出报文学到基座窗口后，之后每一枪先按 `FastWindow` 阶梯压副本——要一个新的会话字段
  和一条新旋钮，等真报告。
- 日志区不插「退回了哪几条」的永久提示，只有状态行一句；细节看会话文件。
- `MAX_OUTPUT = 5000` 不动；`fetch` 的截断尾注不改（网页没有行号可续）。
