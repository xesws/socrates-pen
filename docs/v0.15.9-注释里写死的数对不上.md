# v0.15.9 — 两处注释里写死的数，都对不上

> 日期：2026-08-21。只改注释/docstring，行为零改动。审查 Agent `reviewer-facts` 报的。

## 病在哪

写死在注释里的计数会漂，而且漂了没人发现——**没有任何测试会因为注释过期而变红**。

### 1. `scripts/check-css.mjs:2` 写「三条」，实跑 7 项

```
$ node scripts/check-css.mjs
...
7 项全部通过
```

七项守的是五个不变量：零硬编码色值 / `sp-chips` 的 `@container` 顺序 /
`sp-quote` 的 `@container` 顺序 / 所有动画被 `prefers-reduced-motion` 覆盖 /
进度条主规则 / 进度条的槽 / 减少动态效果时不许整条藏掉。

**这条的传染性最强**：公开仓 README 的测试闸门表是照抄这句注释的，注释错了
README 跟着错。

### 2. `pen/probe.py:220` 的 docstring 写「七处「第三拍 · 出身」」

那个「七」说的是作者自己那本 SWE 手册，**没进公开仓**。随仓公开的演示教材实跑是
**4 处**（L92 / L343 / L652 / L924）。公开仓的读者照着 docstring 去数，必然对不上。

## 改法

两处都**不再写死条数**，并在注释里写明为什么不写死。`third_beat_sections` 的
docstring 顺带补上「书里没有『第三拍』时白名单为空 → `vs_real` 轴永不出题」，
和 README「还欠着的」那条对上。

- 实跑 `third_beat_sections(build_index(docs/demo/从零手写DQN.md))` → 4 处，
  行号 92 / 343 / 652 / 924，和审查报的逐个吻合
- 两仓 `pytest pen/tests -q` → 485 passed；`npm test` 162 项；`tsc` clean
