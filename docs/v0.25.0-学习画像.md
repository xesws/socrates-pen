# v0.25.0 — 学习画像：一张会长的雷达，和它每一分的来路

> 日期：2026-09-03。起因是 v0.24.0 补齐日志之后，读者要的那份「我作为学习者的强弱项」——
> 雷达图、最爱问什么、在哪儿卡住。调研报告（`docs/research/2026-09-03-学习者强弱项调研.md`，
> 未入库）用手工编码把 Level 7 那场 78 轮对话打成八轴，读者看过说「基本符合预期」，并定了四条：
> **轴不是固定的，是动态增长的**（3→5→8→…→30），圆盘要随点增多变密；
> **「轮数」和「长弧线未收口」排在弱信号最前**——逮着一个 citation 连续追问很多轮就是不了解，公式我来 balance；
> **报告是面板不是笔记**，sidebar 右上角一枚小按钮，独立面板页，不写笔记、不改 working directory，
> 既看当前文档也聚合当前 vault 下所有文档；**颗粒度至少 10 分制**。
> 追问四件事的答案：逐轮编码**一律主模型**（思考档同主对话）；**打开面板时增量跑**；
> v0.24.0 之前的**旧行只进频率统计**；**规则分与 BKT 并列**显示，不平均。

## 读者看到的

侧栏那排图标多了第六枚（`radar`，1.5.x 的 lucide 没有就退到 `target`）。点开是一个独立页签「学习画像」，
跟着当前打开的 Markdown 笔记走：

| 这篇笔记 | 面板显示 |
| --- | --- |
| 没在苏格拉底里问过 | 一句提示 + 下面这个库里已有的书 |
| 问过、没分析过 | 「这本书有 N 轮对话，还没分析过」+ **分析这本书**（第一次全量要点一下：按轮计费，不能一打开就替读者花钱） |
| 分析过、又聊了新的 | 打开即自动补编，确定型进度条「已编码 x / N · 本次 tokens」 |
| 分析过 | 雷达 + 轴表 + 书架 |
| 没配钥匙 | 已有的画像照常显示，一行静音提示，不红 |

雷达：第 i 根轴永远在 θ = −π/2 + 2πi/n，顺序就是它第一次出现的顺序，永不重排；环 2/4/6/8/10 与分数
同一尺度；未评的点画在最内环、空心、不进多边形——画在 0 会把「没数据」读成「崩了」；超过 12 根轴只标
最弱 3 和最强 3 的名字，其余靠悬停。轴表按最弱在前、未评在后；每根轴展开能看到定义、**「这一分怎么来的」**
逐条、自陈盲区、每条证据的本地时间 / 第几轮 / 类型 / 读者原话。书架列出这个库里每本书的轮数、轴数、
最弱三轴、问得最多的三轴；同一本书登记过两次（路径变了 id 就变）并成一行，标「2 次登记合并」。

「重算」是面板内两步确认（按钮变「确定重算？」+ 取消），不用 `window.confirm`。中途切到另一本书，
在途的 POST 立刻作废；关掉页签也是。

## 怎么找到的

**分怎么打，先在纸上钉死。** 调研报告那张 78 轮的编码表按 5 分制打过一次；读者说 5 分不够细，
按 10 分制重打，排序不变：磁带 1 / CI 1 / Python 1 / HTTP 2 / 流式 3 / SDK 7 / agent 8（原始 9，
证据只有 3 轮封顶 8）/ 术语英文未评。这张表**只含轮号、类型、轴、判定，不含一个字的原话**，
成了 `pen/tests/test_profile.py` 里的回归 fixture——规则一动它就红。

**真跑第一版抓到一个 bug。** 对 `~/.socrates-pen/trajectories/swe-agent-10e8fd2c.jsonl`（107 行，
含那场 78 轮）用读者自己的主模型（`gemini-3.8-flash`，thinking low，走 Google 的 OpenAI 兼容端点）
逐轮编码：10 枪、25.3 秒、入 35,105 tok / 出 6,944 tok。结果 12 根轴里有三组重名：
「HTTP 状态码与协议规」×2、「Pydantic与数据校」×3、「Python生成器与迭代」×4。病因：轴名超过
`NAME_MAX`（当时 12 字）被截断存下，下一批模型再提原名「HTTP 状态码与协议规范」（13 字），
和截过的存名对不上，当成新轴。修法：截断时把原名记成别名，归并时名字和别名都比；`NAME_MAX` 放到 16。
加了一条测试先红后绿。修完 `force` 重跑：10 枪、28.9 秒、入 34,205 / 出 7,157，**4 根轴**，
没有重名。这份缓存现在就在 `~/.socrates-pen/profiles/swe-agent-10e8fd2c.json`，插件打开面板读的就是它。

**全部 107 行都是旧格式**——包括今天 00:40 写的最后一行（`assistant_preview`、没有 `phase`），
说明读者正在跑的 sidecar 还不是 v0.24.0。按读者的决定旧行只进频率，所以真数据上四根轴全是「未评」，

Python 迭代器与生成器 5 轮；另有 38 轮是写回 / 空芯片这类操作记录。

**为了把算分那条路也在真数据上走一遍**，把这份轨迹复制到临时目录改成新格式（导师全文从会话文件
`ui_messages` 按顺序接回，107 行里 75 行接到了全文，其余用 200 字预览），再跑一次：10 枪、32.1 秒、
入 65,773 / 出 7,260（全文比预览长一倍多）。模型自己长出 7 根轴，分数：

## 病根

现有 `diagnose.aggregate` 只会数 hits：一处被问几次。它没有「一根轴连着问了几轮」「说懂了之后
又回来」「自陈盲区」这些概念，轴也不是能力而是章节——读者要的画像它给不出来。

## 改了什么

**规则只有一个定义点：`pen/profile.py` 顶部的常量块。** 插件不复算任何分数，「怎么算的」字符串由
sidecar 按 `Accept-Language` 生成，参数只有数字和轮号，绝不带读者原话。

| 规则 | 分 | 上限 |
| --- | ---: | --- |
| 起评 | 6 | |
| **追问弧线**：同轴连续 ≥3 轮（轮号间隔 ≤2）、≥2 轮在问；扣 `ceil(轮数/3)` | −1…−3 | 单条 −3 |
| 弧线里没有「说懂了」（**未收口**） | −1 / 条 | 弧线合计 −5 |
| **回头**：说懂了之后同轴第一次再问；按回点去重；回来后到下一个「说懂了」之前求证被确认的算核对，不算回头 | −2 / 次 | −4 |
| 自陈盲区 | −1 / 次 | −3 |
| 求证被纠正（不含已算作回点的那次） | −1 / 次 | −2 |
| 求证被确认 | +1 / 次 | +3 |
| 顶回导师且对 | +1 / 次 | +2 |
| 自己提的模型被导师采纳 | +2 | |
| 说懂了之后没再回来 | +1 / 次 | +2 |
| 证据 < 3 轮未评；< 6 轮封顶 8；夹到 1–10 | | |

「在问」= ASK、GAP、DEMAND、被纠正的 VERIFY。**BKT** 固定参数 `P_INIT 0.3 / P_LEARN 0.15 /
P_SLIP 0.1 / P_GUESS 0.2`，观测流按时间：确认→1、纠正→0、顶对→1、顶错→0、盲区→0；
ASK / DEMAND / DECLARE / META 不是观测。

**编码器**（`profile.code_next`）：七类 `ASK / VERIFY / DEMAND / REJECT / GAP / DECLARE / META`，
优先级 GAP > DECLARE > REJECT > VERIFY > DEMAND > ASK；轴先从已有的选 id，确实没有才提
`{name, definition}`，新轴是能力不是章节；`verify` 只读导师回复判；`evidence_quote` 必须是读者原话的
子串，机械核对，不是就整条作废、`attempts + 1`，三次放弃；批 10 轮一枪、**每枪后落盘**、厂商异常先落盘再抛；
按 handbook 持锁，两个面板同时点不会双编。确定性的不调模型：approve 行、写回芯片、空正文 → META；
只点了芯片没打字 → 送模型只取轴，Python 强制 ASK。`_create` 照 `probe._create`：非流式、不带 tools、
`timeout = probe_timeout_s`，推理档并 `providers.thinking_wire`（方言表仍只有 `providers.py` 一份）。
花销记在缓存里、随响应回，**不进 `/v1/usage`**（同 diag 的做法：按 handbook 索引，没有会话可挂）。

**三个端点**：`POST /v1/handbooks/{id}/profile/code`（`LlmOverrideBody` + `max_batches` + `force`，
`max_batches` 夹到 1..10 不 422；无模型 400；厂商错 400 `{code, message}` 与 `/v1/chat` 同一张码表）、
`GET /v1/handbooks/{id}/profile`（没缓存也 200，`axes: []`，**不落盘**）、`GET /v1/profiles?vault_root=`
（按登记时的 `allow_root` 过滤，坏根 / 空根 400；只读缓存，不调模型）。

**插件**：`src/views/ReportView.ts` 第二个 `ItemView`，挂同一个 `.socrates-pen` 类；雷达几何在
`src/radar.ts`、书架合并与本地时间戳在 `src/profile.ts`，两者零 import；`createSvg` 逐节点建，绝不 innerHTML。
`main.ts` 把「露到右侧栏」那三步收进 `revealSide()`，两个视图共用（仍不许 `revealLeaf`）。
`PenView` 第六枚按钮只按 sidecar 通不通灰，不按 busy、不按 handbookId——没登记的笔记也能看书架。
增量循环带停滞保护：连着 3 枪既没编出新轮次、`remaining` 也没变小就停并报错，= 服务端 `MAX_ATTEMPTS`，
模型一直吐坏 JSON 时第三枪服务端放弃那批、循环正常收口。

## 二审：Codex review 后修的

提交前用 Codex CLI（gpt-5.6-sol，推理档 xhigh，只读沙箱）把 `pre-0.25..HEAD` 整段 diff 过了一遍：18 条，
其中 2 条我自己先抓到了。修了 16 条，不修 2 条。

必修，本轮引入且明确：

- **GET 在内存里补确定性编码，没跑过 `/code` 的书 `n_coded` 就不是 0**（high）。一条写回 META 就让面板把它
  读成「分析过了」，一打开就自动付费补编，绕过了「第一次要读者点一下」。`report()` 不再补；`/code` 之后 META
  才算编过。
- 停滞保护只看 `coded`。最后一批全被服务端放弃、只剩一条没试过时，`remaining` 从 31 掉到 1 而 `coded == 0`，
  面板误报停滞、那一条永远不试。现在 `remaining` 变小也算推进。
- `resolve_axis` 在引文校验之前调用：作废的编码留下一条没有证据的空轴，占 `MAX_AXES` 名额、以「未评」上雷达。
- 只点芯片的轮次模型答 META 会绕过「强制 ASK」，永远丢出统计。
- 非 META 编码模型给 `axis: null` 照存：`n_coded` 加一，任何轴的频率和证据里都看不见它。轴没满就当没编好，
  记一次 attempt。
- `bool("false")` 是真：`adopted` 只认真布尔，否则白加 2 分。
- `load_cache` 不验容器形状：合法 JSON 里 `codings` 是个 list 的话，`.items()` 把两个 GET 都炸成 500。
- 缓存写不进去（目录只读、磁盘满）走 `except OSError` 报成「厂商不可达」：读者去查网络，重试再付一遍钱。
  现在是 `ProfileStoreError` → 500，文案单独一条。
- 切语言只重画不重取：`why` 是服务端按 Accept-Language 现算的，报告态下重 GET 一次（不编码、不花钱）。
- 书架合并在服务端裁成 top 3 之后才做：两次登记里都排第 4 的轴合起来本该第一，却在合并前就丢了。
  每本书的每条轴带 `asked`，插件从全部轴合并后再取前 3。
- 超过 `ALIAS_MAX` 的同一个长名字第二批再来不认得，建了第二条：先夹到 `ALIAS_MAX` 再比、再存。
- 书架两枪共用一个代次，慢的那枪后到把新计数盖回旧的：书架有自己的序号。
- 弧线合计封顶 −5，`why` 却逐条写未封顶的原始扣分，逐行相加对不上最终分：超了就多一行「合计 −8，封顶 −5」。
- `max_batches: int` 让 `"many"` 在夹紧之前就 422，和注释写的「看不懂当缺省」相反：类型改 `Any`。
- 编完了再点一次 `/code` 也写盘、刷新 `updated_at`（面板上的「上次编码时间」）：什么都没变就不写。
- check-report 里「辐条末端在外环上」写成 `abs(hypot(…) − 0) >= 0`，对任何有限坐标恒真——假绿，改成真量半径。

不修：

- 请求体里的 `api_key`：`LlmOverrideBody` 是 `/v1/chat` 沿用的基类，不是本轮引入；插件侧一个字都不上行，
  由 `check-key.mjs` / `check-api.mjs` 守着。
- `_is_quote` 去掉全部空白再比：有意的容错。模型引中文原话时常把空格和换行吃掉，真跑三次没出过一条假引文；
  改成严格子串会把大量正确的编码作废。

每条都先有一条红的测试再修：`test_profile.py` +11（旧代码上 11 条全红），check-report 的书架用例换成
「两边都第 4 的合起来第一」那个形状（旧 `profile.ts` 上跑不过）。
