# v0.23.0 — 厂商方言表 + 体检按主对话那一枪的真实形状打

> 日期：2026-09-02。承读者一句「关于 thinking level 这块，必须得任何一个模型厂商
> 过来它都得兼容」，以及上一版留下的那个洞。

## 读者说的

> 「只要是带 think 或者 effort 的，默认都要映射成我们的 thinking level，它得自动去
> 映射才行。比如说 Google、Meta、OpenAI、Kimi、GLM、DeepSeek，这些都得兼容才对。
> 所以我建议你直接在配置 model 的时候，写一个下拉的 tab。对于每一个 model，都应该
> 有自己的配置方法，不要像现在这么简单粗暴，只是填一个 API key。」

同一条消息里还答应了上一版结尾提的那件事：把体检改成「按主对话那一枪的真实形状打」。

**这两件是同一个病的两半。**

## 病根

`thinking_wire()` 是全仓唯一按型号名分叉的地方，v0.22.5 之后它认三家：celeris、
Gemini、GLM。掉到最后那个默认分支的一律发 DeepSeek 的方言：

```python
out["reasoning_effort"] = lv
out["extra_body"] = {"thinking": {"type": "enabled"}}
```

`extra_body` 里的键会被 OpenAI SDK **摊到请求体顶层**。所以任何没有 `thinking`
这个字段的兼容层收到它就当场 400。上一版修的是 Google 那一家，可

| 厂商 | 今天会怎么炸 |
|---|---|
| Kimi K3 | 官方明写「should not pass the thinking parameter」 |
| Meta muse-spark | `reasoning_effort:"none"` 直接 400，而它只认 minimal/…/xhigh |
| OpenAI gpt-4o | 非推理型收到 `reasoning_effort` 就 400 |

一家一家打补丁是打不完的，因为**默认分支本身就是错的**：把一家的私有拼法当成
所有人的默认。

## 而体检看不见它

`preflight.check()` 的探针**不带 thinking_wire、不带 tools、不流式**。也就是说
一个推理方言不认、或者压根不支持工具调用的节点，状态栏给的是**绿灯**——读者要
等对话里撞红字才知道。v0.22.5 那个 400 就是这么漏过去的。

上一版的注释还把这件事写成了优点（「推理档配错了是另一条错误，混进来会让一个 400
说不清是哪一格的问题」）。那个顾虑是真的，但结论下反了：**分不清是可以打出来的**，
见下面的减配梯子。

## 一、`pen/providers.py`

厂商 → 四档推理映射的唯一定义点。形状是全声明式的：一格一个**字面的线上 payload**。

```python
@dataclass(frozen=True)
class Shot:
    kwargs: dict[str, Any]    # 并进 create() 的字段。{} = 什么都不发
    keep_reasoning: bool      # 这一枪要不要留住节点吐回来的思考正文

@dataclass(frozen=True)
class Provider:
    key: str
    match: tuple[str, ...]                    # 自动识别：型号名含这些子串
    base_url: str                             # 设置页预填
    variants: tuple[tuple[str, str], ...]     # (型号名正则, 变体名)，第一个命中
    table: dict[str, dict[str, Shot]]         # 变体名 → 四档
```

`thinking_wire` / `thinking_on` 退化成两行转发，六个 `_is_*` 谓词整体删掉。

### 九家

| 厂商 | off | low / medium / high | 出处 |
|---|---|---|---|
| `generic` | `{}` | 裸 `reasoning_effort` | **永不发 extra_body** |
| `deepseek` | `thinking:disabled` | effort + `thinking:enabled` | 官方文档 |
| `glm` | 5.3 强制 → effort low + enabled；其余 disabled | 5.2+ 发 low/high/max | 既有行为，逐字保留 |
| `celeris` | `effort:none` | low / medium / **xhigh** | **本机实测** |
| `google` | 3+ → low；2.5 → none | effort 直传 | 官方文档（v0.22.5） |
| `openai` | 推理型 → low；**gpt-4 系列四档全空** | 推理型直传 | 非推理型收到就 400 |
| `kimi` | K3 → low；K2.x → disabled；moonshot-v1 全空 | K3 low/high/max | 官方文档 |
| `meta` | `effort:minimal`（none 会 400） | effort 直传 | 官方文档 |
| `openrouter` | `{}` | 裸 effort | 只能显式选 |

> **只有 celeris 那一行是实测的**（v0.22.0 每一格都打过一枪量出来）。其余全部来自
> 各家官方文档。每个 `Provider` 的 docstring 里都写了这一行的出处——别把两种强度
> 当成一回事。猜错的兜底不是小心，是第二节那个体检。

### `keep_reasoning` 为什么和 kwargs 住在同一格

v0.22.4 定的规矩是「`thinking_on` 从 `thinking_wire` 推导，不另写一张表」，理由是
「UI 的 off 对某些型号仍是开着的」这件事只有 wire 知道。这一版把它放进同一个
`Shot` 里，**不是放松那条纪律，是收得更紧**：仍然只有一个定义点，只是那个点从
「一个函数的返回值」变成了「格子本身」。推导做不到的那一格也补上了——「什么都不发」
对 Meta 是在思考、对 gpt-4o 是不在，wire 里看不出来。

取值规则写在字段的注释里：**只有我们明确发了「关」才写 False，拿不准一律 True。**
两种猜错的代价差得很远——猜 True 而节点不思考，它不吐推理，没东西可留，代价是零；
猜 False 而节点在思考，丢掉那段正文，下一枪就是 v0.22.4 那条 400。

### 两条有意的行为变化

1. **DeepSeek 的 off 从「什么都不发」改成明确 `disabled`。**
   官方文档：「思考模式默认启用，默认工作强度 high」。也就是说旧的空 dict 根本不是
   off——它是满档思考，外加 `thinking_on` 判成 False 把那段推理扔掉，正好凑出
   v0.22.4 那条 400。low/medium/high 三档逐字不变。
2. **认不出的型号不再收到 `extra_body.thinking`。** 这是整版的主要修复。
   DeepSeek / GLM / Kimi 靠 `match` 命中各自那一行，行为逐字不变。

## 二、体检按真实形状打

### 不照抄形状，直接调 `llm_create_kwargs()` 本人

```python
kwargs = llm_create_kwargs(cfg, messages=probe_messages(sent_image), tools=schemas())
```

`llm_create_kwargs` 就是「主对话那一枪长什么样」的定义点。照抄一份就是第二个定义点，
而「两个闸不同源」这个仓踩过三次。这么写之后，主对话那一枪将来长出新字段，探针
自动跟着长。

`max_tokens` **整个拿掉**。原先那个 `max_tokens=1` 是我们为省钱加的字段，推理型
模型常对最小输出有要求，于是体检招来过读者根本撞不上的 400，再把它报成读者的配置
问题（v0.22.3 为此补了「分不出类就再打一枪」）。现在省钱靠**收到第一片就断开**，
请求体里一个我们自造的字段都没有——那类误报按构造消失，比补一枪干净。

### 减配梯子

四样东西任何一样不认都是同一个 400，而读者的补救动作完全不同。所以失败时逐级减：

```
① 全形状              成 → 绿灯
   不是 400（401/404/连不上）→ 直接报，减了也白减
② −推理档             成 → no-thinking
③ −推理档 −工具        成 → no-tools
④ ③ −stream_options   成 → no-usage
⑤ ④ −stream           成 → no-stream
   减到光了还错 → 沿用原有分类
```

三条纪律：**只有 400 才进梯子**（坏钥匙一枪定案）；**报的原话用第①枪的**（后面几枪
是我们为了定位自己造的局面）；**这一级没减掉任何东西就跳过**（推理档是 off 时 wire
本来就是空的，白打一枪不说，还会把「我们压根没发推理字段」报成 no-thinking）。

梯子只在失败路径上跑，所以日常绿灯**恰好一枪**。本机对着假节点量过：

```
=== 第 1 枪 ===
  键: ['messages', 'model', 'reasoning_effort', 'stream', 'stream_options', 'tools']
  tools: ['read_file', 'edit_file', 'fetch']
  max_tokens: （没有）
```

失败那一路是两枪：全形状（顶层带着摊平的 `thinking`）→ 减掉推理档 → 通过 →
判词 `no-thinking`。

### 四个新码

`no-tools` / `no-stream` / `no-usage` / `no-thinking`，各自一句人话。占位符只能用
`{kind}` / `{model}` / `{detail}`——`app._slot_report` 那句是写死的三个参数，用别的
名字就是一个 500（v0.22.2 已经用一个 500 换过这条教训）。

`no_thinking` 的文案把出路说全了：「到设置里把「模型厂商」选成对应的那一家，或把
Thinking 设为 off」——这正是两节之间的接缝。

## 三、设置页

```
常用
  ├ 模型厂商    [ 自动（按型号名判断） ▾ ]
  │             提示行：官方地址 · 型号名长什么样 · 思考关不关得掉
  ├ Base URL    选厂商时预填
  ├ 模型名 / API Key / 图像理解 / Thinking
Fast Mode 区同形，多一格「快模型厂商」
```

- **默认「自动」**，所以老库升级一个字都不用改，请求体里连 `provider` 这个键都不出现。
- **预填绝不覆盖读者手打的地址**：只有空着、或者还停在另一家的默认值上时才填。
  走网关、走中转站的人最需要这个下拉，而他们填的恰恰是一个不属于任何一家的地址。
- 厂商名是专名，按仓库惯例不进词表；进词表的只有「自动」「通用」两档和每家的提示语。
- 改厂商 → 当场 `this.display()` 重画（照语言下拉的手法），首画那行
  `paintKeyStatus(el, true)` 顺手把体检重跑一遍。

### 推理档从「不打枪」挪进「要重检」

`configSignature` 是体检节流的全部依据，`check-preflight.mjs` 里原先有一条断言
「改 thinking 档 → 不打枪」。体检现在按真实形状打，推理档就在那一枪里，换一档真有
可能把一套本来能用的配置打挂——**那条断言从这一版起是一条谎**，挪进 `MOVES`。

## 四、闸

新增第 11 道 `scripts/check-providers.mjs`：前端下拉的键必须与 `pen/providers.py`
的 `PROVIDERS` 逐个一致。为什么非机械守不可——读者选了一个后端不认的键**不会报错**，
`provider_for()` 认不得就当没选、静默落回 generic。设置页显示选着 Kimi，实际按通用
写法发，**没有任何症状**。这是「两个闸不同源」的又一个形状，只是这次连红字都没有。

`pen/tests/test_providers.py` 遍历每个 (厂商, 变体, 档位) 格子，断言线上只出现
`reasoning_effort` / `extra_body` 两个键、取值在白名单里。表写错了当场红，不用等真节点。

### 一条走整条路的闸

上面那些全在直调 `thinking_wire()` 或者手搓 `LLMConfig`，而读者走的是
设置页 → `llmPayload` → 请求体 → `LlmOverrideBody` → `merge_llm` → `LLMConfig`
→ `llm_create_kwargs` → `thinking_wire` 这一长串。中间任何一环忘了透传 `provider`，
上面那些闸一条都不会红。所以补了 `test_the_chosen_provider_reaches_the_wire`：
同一个假节点（只嫌顶层 `thinking`），选 generic 得绿灯、选 deepseek 得 `no-thinking`。
**验过它真会红**——把 `merged()` 里那行 `provider=self.provider` 删掉就当场失败。
