# v0.15.3 — 补 v0.15.1 架空掉的一条断言

> 日期：2026-08-22。**只动 `pen/tests/`**，产品代码一行不改，插件 semver 不动。

## 病：v0.15.1 自己捅的

v0.15.1 让 `conftest.py` **无条件**把 `config.DEFAULT_HANDBOOK` patch 到
`pen/tests/fixtures/default_handbook.md`。那一版是对的——但它顺手把
`test_config.py:282` 那条断言变成了**永真**：

```python
if (config.REPO_ROOT / "SWE-Agent通关手册v2.md").is_file():
    assert config.DEFAULT_HANDBOOK.is_file()      # ← fixture 必然存在，永远为真
```

这条断言的原意是「实验室检出里，`DEFAULT_HANDBOOK` 这个常量指向的那份真教材必须读得到」。
patch 之后它验的是 fixture，**原意整个丢了，而且不会以任何形式报出来**。

顺带两处 v0.15.1 留下的脏东西：

- `test_app.py:16` / `test_diagnose.py:10` 的注释被 v0.15.1 的正则替换连坐，
  变成了病句：``不写 `from pen.config import config.DEFAULT_HANDBOOK` ``。
- `test_index.py:5` 的 `from pen.config import DEFAULT_HANDBOOK` 是**故意**的冻结绑定
  （`test_real_handbook_index_readonly` 必须验那本 13083 行的真教材，断言
  `n_lines > 10000`、80 道 Q、七个 Level 各有 Q1），但没写明。
  v0.15.1 的提交信息刚说过「冻结绑定是 bug」——下一个人照着改，实验室仓对真教材的
  唯一覆盖就静默没了。

## 改法

1. `test_config.py`：模块顶部加
   `from pen.config import DEFAULT_HANDBOOK as PRISTINE_DEFAULT_HANDBOOK`。
   模块 import 早于任何 fixture，拿到的是 patch **之前**的原值。
   断言改成验它；并补两条反向断言，防「fixture 悄悄失效、测试又跑回真教材上」
   （那会让公开仓重新变红而没人发现）：

   ```python
   assert config.DEFAULT_HANDBOOK != PRISTINE_DEFAULT_HANDBOOK
   assert config.DEFAULT_HANDBOOK.name == "default_handbook.md"
   ```

2. `test_app.py` / `test_diagnose.py`：注释改回人话。
3. `test_index.py`：写明那个冻结绑定是故意的，以及改掉它会丢什么。

**两处冻结绑定的方向是相反的，所以两边都必须写清楚为什么**：
`test_app` / `test_diagnose` 要 patch **之后**的（它们只需要「一本能读的书」），
`test_config` / `test_index` 要 patch **之前**的（它们验的正是那个常量本身、和那本真书）。

## 怎么发现的

我自己交代给审查 Agent 时点名要它查这一条（「v0.15.1 那个无条件 fixture 会不会掩盖
某些原本该由真教材暴露出来的问题」），等结论期间自己先去看了 `test_config.py:281`。
**这类「改对了一件事，顺手架空一条断言」的伤，测试全绿是照不出来的。**
