# v0.18.0 — API key 迁出 vault：sidecar 托管 + 自动迁移

> 日期：2026-08-23。产品行为变更：钥匙的存放位置与设置页交互都变了。

## 病

`data.json`（`.obsidian/plugins/socrates-pen/data.json`）里的 `settings.apiKey` 是明文。
这个文件跟着整个库走：Obsidian Sync、iCloud、git。库一旦进公开仓或共享云盘，钥匙即泄露。
设置页那句文案（v0.16 之前的 `setIntro2`）甚至自己承认了这件事。

结构性根因：**真正用钥匙的只有 sidecar**（`tutor.py` / `probe.py` / `diagnose.py` 建
OpenAI client），Obsidian 端只是"代收"再随每个请求转发。源放在一个必然被同步的文件里，
消费方却在另一个从不被同步的进程里。

## 改法

**钥匙的唯一归宿从 vault 挪到 sidecar 家目录：`~/.socrates-pen/llm.json`（0600）。**

### 1. sidecar 托管层（`pen/config.py`）

- `read/write/clear_managed_key()`：读写 `PEN_DIR/llm.json`。写入走临时文件 + `rename`，
  显式 `chmod 0600`（目录 `0700`），半截写不在正主位置留明文。
- `resolve_llm()` 优先级变为**托管文件 > 环境变量/.env**。托管来源报 `key_source:
  "sidecar"`；env 路径原样保留，伺候无 UI 场景（headless、CI）。
- `merge_llm()` 的"钥匙不跨主机挪用"规则（`_host_of`）对托管层同样生效：托管文件里
  的 `base_url` 就是这把钥匙的宿主。
- `llm_public_status()` 增加 `key_tail`（末 4 位；短于 12 字符的钥匙不露）。仍然不含
  密钥全文。
- 新端点（`pen/app.py`）：`PUT /v1/llm/key {api_key, base_url?}` 写托管文件；
  `DELETE /v1/llm/key` 删除。**没有任何 GET 能拿到全文。**
- `LlmOverrideBody.api_key` 继续接受：旧版插件对上新版 sidecar 不断。

### 2. 插件端不再落盘（`src/`）

- `PenSettings` 删掉 `apiKey` 字段（类型层禁绝）；`loadSettings` 把老 data.json 里的
  明文值装进**只活在内存里的** `migrateKey`。
- `llmPayload()` 永不再携带 `api_key`——那条"每个请求把 vault 里的明文钥匙发一遍"的
  通道整个拆掉。
- 设置页 API Key 行改**只写**：粘贴后回车/失焦即 PUT 给 sidecar，本地任何文件都不存；
  旁边一枚「清除密钥」按钮；状态行显示 `key_source` + `key_tail`（事实在 sidecar，
  vault 里永远没有副本可显示）。
- 启动迁移（`main.ts migrateKeyOut`）：`migrateKey` 非空 → 等 sidecar 健康（最多
  45s，onload 刚 kick 过 ensure）→ PUT → 成功后 `saveSettings` 落一份没有钥匙的
  data.json → Notice 告知新位置，并提醒"库曾被同步/提交过就轮换钥匙"。
  **失败（sidecar 没起 / 旧版 sidecar 404）就整场放弃**：钥匙留在内存下次启动再迁，
  data.json 原样不动——绝不为了"这次先能用"把明文写回去。
- 健康行（`PenView.probeHealth`）改读 `health.llm`：`key_source: "sidecar"` 显示
  「钥匙已存本机 …尾号」；env 来源照旧显示「开发回退 {变量名}」。
- 新增 `scripts/check-key.mjs`（挂进 `npm test`）：跑编译后的真代码，断言
  `llmPayload` 产物永远不含 `api_key` 键（连运行时硬塞进 settings 对象的金丝雀都
  带不出来）、`DEFAULT_SETTINGS` 无该字段。谁要是把旧通道接回去，看门狗当场红。

### 3. 为什么不用别的方案

- **官方 SecretStorage（Obsidian 1.11.4+）**：要抬 `minAppVersion` 砍掉 1.5.0–1.11.3
  的用户；且初版底层同为明文 LevelDB（加密在路线图上）。日后抬版本门槛时可再评估。
- **localStorage**：非官方、随清缓存丢、跨插件可读；而且钥匙还是要逐请求喂 sidecar，
  消费方和存放地仍然分家。
- **macOS Keychain（python keyring）**：引入原生依赖，pip 安装失败率上升。`0600`
  文件是 gh-cli / aws-cli 的通行做法。
- **只劝用户 .gitignore data.json**：治标——Sync / iCloud 照漏，且 git 用户往往已经
  提交过。

## 迁移与诚实边界

- 自动迁移只动**当前文件**。git 历史 / 云端历史里的旧钥匙清不掉：文档（README 两语）
  明确指引 `git filter-repo` / BFG，并建议直接轮换。
- sidecar 是机器级共享：一台机一把托管钥匙，多 vault 共用（env 覆盖仍在）。
- `data.json` 本身仍会同步（sidecar 地址、旋钮、笔记绑定）——里面已经没有任何秘密。

## 审核追记（同日，grok-4.6 xhigh 独立审核三轮提交后修）

- **P0 `saveSettings` 会在迁移失败后把 data.json 里的钥匙一并抹掉**：首次「用当前
  选区」就触发 `bindNote → saveSettings`，而 PUT 尚未成功——内存里的 `migrateKey`
  关掉 Obsidian 即失，等于永久丢钥匙。改法：`migrateKey` 非空期间，saveSettings 把
  钥匙**原样写回** data.json；PUT 成功后才停止携带。「绝不回写明文」指不新增落点，
  不是把盘上已有的唯一副本弄丢。原文那句「失败就整场放弃：钥匙留在内存」随之作废。
- **P1 旧 sidecar 挡住升级还一声不吭**：keepAlive 默认开 + `ensure()` 见健康就短路，
  常驻的 0.16 进程既不升级也不认 `PUT /v1/llm/key`，而新插件已不再随请求发 key——
  迁移循环改为 PUT 重试 45 秒，404/405 时弹 Notice 指路（停止/杀旧进程再启动），
  不自动杀非本插件拉起的进程（README 既定政策）。
- 其余同批小修：`write_managed_key` 失败路径清理 `.tmp`；端点测试隔离
  `OPENAI_API_KEY`/`DEEPSEEK_API_KEY`；换会话 Notice 在跨笔记 + 目标旧会话过期时
  也能出（原先被 renewed 吞掉）；`ask` 按钮的禁用式两处统一；设置页存/清钥匙后
  唤醒打开中的面板重探；换 Base URL 时若现有钥匙属别的主机，当场提示重贴。
  README 里 `PenView.ts:788` 的行号漂移改为 849。
