# v0.24.0 — 日志要够看：本地时间、全文、真锚点、追问入库

> 日期：2026-09-03。起因是读者要一份「我作为学习者的强弱项画像」——雷达图、最爱问哪类概念、
> 在哪儿卡住。我把现有轨迹翻了一遍，列出四条数据缺陷准备「以后再说」。读者当场说：
> **「架构得补一点信息，不然日志不够看。时间（local time）一定得补，不然没有时间我们怎么分析呢？
> 数据质量缺陷这一块所有东西都要补。补完之后再做 research。」**

## 读者看到的

一场 64 轮、2 小时 49 分、`spend.chat` 入 10,764,129 tok 的对话，落盘之后长这样：

| 想看的 | 实际有的 |
| --- | --- |
| 每句话什么时候说的 | `ui_messages` 一条时间戳都没有；轨迹行有 `ts`，但是 UTC，读者要自己减八小时 |
| 读者原话 | 轨迹里截到 240 字；第 11 轮那句 300 多字的「英文术语必须精准，我面试要用」只剩前半句 |
| 苏格拉底答了什么 | 轨迹里只留 200 字预览；全文只在会话文件里，而会话文件七天就被 retention 扫掉 |
| 这一轮在手册哪里 | **66 行里 36 行 `level="封面"`、`start_line=1`**，可 `selected_chars` 有 285–873——选区明明在，位置是假的 |
| 抛给读者的两条追问、读者点没点 | 没记。点追问和自己打字发到后端长得一模一样 |
| 写回批准之后那半截 | 一个字没记。`/v1/chat/approve` 的 finally 里是一行 `_ = ok` |
| 走的快模型还是主模型 | 没记 |

`diagnose.aggregate` 靠 `is_curriculum` 把「封面」全过滤掉，于是现有的「薄弱点」聚合器
**看不见这场对话的 55%**——磁带那 11 轮（04:50–05:03）、HTTP 的开头（02:48）和结尾（05:36）全在里面。

## 怎么找到的

「封面」那 36 行不是没选文字。顺着插件查：`src/selection.ts` 在阅读视图下拿 `linesFromQuote`
把划到的渲染文本对回原文行号，**对不上就回退 `{startLine: 1, endLine: 1}`**。1 是一个真实
的行号，sidecar 老老实实 `idx.locate(1)` → 封面。

把 `linesFromQuote` 逐字移植成 Python，拿这本手册（32,070 行）和轨迹里那 13 段不重复的选区实测：

| 匹配规则 | 对上的 |
| --- | --- |
| 折叠空白后找子串（v0.23.1 的写法） | **0 / 13** |
| 只留字母、数字、汉字后找子串；整段不中再探开头 48 字、结尾 48 字 | **11 / 13** |
| 剩下两段 | 选完之后手册被写回改掉了（磁带「生态位」那段按读者要求改成了 RL 版本），原文已不存在 |

一段都对不上的原因很直白：读者划的是渲染后的字，原文里夹着 `**` 、反引号、表格竖线、
`#`、`[链接](url)`。折叠空白救不了这些。

那两段「原文已不存在」说明另一件事：**这个缺陷不能靠事后回填补救**。手册每天都在被写回，
今天对不上的明天更对不上。只能在发生的那一刻记对。

## 病根

四条，各是一个「记的时候图省事」：

1. 插件对不回行号时**撒了一个像真的谎**（发 1），而不是说「不知道」（发 0）。
2. 轨迹行按「够 `diagnose` 用」设计，不是按「够分析读者用」设计——截 240 / 200 字，
   不记追问，不记路由。而它是唯一不删不改的记录。
3. 时间戳各写各的：`session.to_dict` 一处 UTC，`trajectory.append_turn` 一处 UTC，气泡零处。
4. 一轮跨两个请求时，第二个请求没人记账。

## 改了什么

**时间只有一个定义点。** 新增 `pen/clock.py:now_iso()`：本地时间、带偏移、到秒
（`2026-09-03T10:47:06+08:00`）。它仍是绝对时刻，`fromisoformat` 一行读回，和旧行的
`+00:00` 混排也不会错，但读出来就是读者墙上那口钟。气泡、轨迹行、compact 的 note、
`updated_at` 全从它来。

**「引文 → 行号」还在插件（`src/locate.ts`），但规则换了**：两边只留字母数字汉字再比，
整段 → 开头 48 → 结尾 48；探针命中只报探针自己覆盖的行（窄而准，不按整段长度外推）；
找不到返回 null，`selection.ts` 发 **0**。

**「0 怎么解释」只在 sidecar（`tutor._place`）**：同一本书里上一处锚点还在且没越界就沿用，
标 `located="sticky"`；否则记在第 1 行，标 `"none"`；正常定位标 `"exact"`。三个值进 anchor，
分析时按可信度用。给模型的 `[邻域]` 也跟着沿用上一处——以前它拿到的是封面那几行，等于没有。

**轨迹行自足**（`pen/trajectory.py` 开头写明了为什么）：

| 字段 | 内容 |
| --- | --- |
| `phase` | `chat` / `approve` |
| `asked_at` · `ts` · `duration_s` | 问的时刻、答完的时刻、等了多久 |
| `user_text` · `assistant_text` | 整句、整段，不截 |
| `offered` | 这轮回复末尾抛出的两条追问 |
| `picked` | 读者这句是点的追问（`dyn` / `deep`）还是自己打的（空）。**在 sidecar 判**，不改协议：上一轮的 `last_chips` 和深挖的 `mark_clicked` 本来就在手上 |
| `route` | `fast` / `base` |
| `anchor.located` | `exact` / `sticky` / `none` |

`/v1/chat/approve` 的 finally 现在追加一行 `phase="approve"`，带 `allow`、后半截全文和钟。

**什么算一轮只在 `trajectory.is_turn` 定。** `diagnose.aggregate` 和 `app._footprint` 都问它，
不然每次写回同一处 hits 翻倍，一轮就成「薄弱」。`load_turns` 不再静默丢掉没有 anchor 的行——
读者的数据不该在读的时候被筛，要筛让消费方筛。

## 闸

- 新增 `scripts/check-locate.mjs`（13 项）：打包真 `src/locate.ts`，粗体 / 反引号 / 表格 /
  标题 / 代码块 / 折叠块摘要各一条，头探针、尾探针各一条，找不到必须是 null。
- pytest 新增 8 条（`test_trajectory.py` 3、`test_app.py` 3、`test_tutor.py` 1、
  `test_diagnose.py` 1、`test_compact.py` 1）。每条都先验过红：`_place` 不接 fallback → sticky 红；
  `is_turn` 不筛 → approve 双计红；`load_turns` 留空对象 → 旧的 `test_corrupt_jsonl_skipped` 红
  （于是空对象照旧跳过，只有「没 anchor 的行」不再丢）。
- 合计：pytest **1014 passed**；前端十二道闸 **488 项**全过。

## 没做的

- **不回填旧行。** 上面说了为什么救不回；而且 sidecar 一直在追加同一个文件，旁边重写等于
  和它抢文件。要做画像的那份分析在内存里按新规则重算锚点，报告里写明哪几行是这么来的。
- 旧行的 `ts` 还是 UTC。`fromisoformat` 认，排序不乱，只是读的时候要自己看偏移。
- `propose_fold_md` 用 `llm_create_kwargs`（强制 `stream=True`）却读 `resp.choices[0]`——
  真节点上必炸。但 `POST /v1/writeback/propose` 在 `src/` 里零调用，是自初始提交就死的路由，
  读者碰不到。另开一版处理。
