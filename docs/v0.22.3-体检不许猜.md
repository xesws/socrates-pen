# v0.22.3 — 体检不许猜

> 日期：2026-09-02。修 `v0.22.2` 自己造的一个误诊。

## 读者说的

> 「我明明关了啊，为什么仍然报错」

截图里两张：设置页的「图像理解」开关是**关着**的；面板顶栏是一颗**橙点**，
后面跟着「节点拒收了图片。这个模型多半没有视觉，把设置里的『图像理解』
关掉，或换一个多模态模型。」

橙点是 `v0.22.2` 刚加的体检在说话。而体检在视觉关着时**根本没有挂图**。

## 病灶：把一个文本猜测用在了「不可能成立」的场合

`looks_like_vision_reject()` 是在报文里找 `image_url` / `vision` / `multimodal`
这些词——它一直是个猜测，只是以前只在真发过图的对话里被调用，所以猜得准。

`v0.22.2` 让体检复用了 `provider_error_code()`，却没有把「这一枪到底有没有
图」这个前提传进去。于是节点因为别的原因回了 400、报文里恰好有个匹配词，
体检就一口咬定「把图像理解关掉」——而读者已经关了。

**没发图的时候，那个结论不是猜错了，是根本不可能成立。**

```python
def provider_error_code(exc, *, sent_image: bool) -> str:
```

`sent_image` 没有默认值，是刻意的：三个调用方各自都知道答案，而漏传的后果
就是这次这一幕。`_create` 问的是**真发出去的那份 messages**，不是 `cfg.vision`
——开着视觉但这场压根没贴过图时，400 一样不可能是拒图。

## 顺带：分不出类的 400，转述节点自己那句话

以前分不出类就回一句「节点拒绝了这次请求。请核对设置里的 Base URL、model
字符串和 API Key。」——三样都核对过的读者看到它，等于什么也没得到。而节点
其实已经说了原因，我们只是没往上传。

```python
def provider_detail(exc, cap=200) -> str:
    """节点自己那句话。**分不出类的时候，转述它远胜过我们再猜一次。**"""
```

转述之后，「不泄钥匙」从顺带变成了必须——这句话会显示在状态栏上，也会进
读者的截图。所以有一道 `_KEYISH` 正则先把 `sk-` / `ck-` 那类串抹成 `[key]`，
并截到 200 字。

## 顺带二：体检不许把自己招来的错报成读者的问题

第一枪带 `max_tokens=1`，图便宜。可**那个 1 是我们自己加的**：推理型模型常常
对最小输出有要求，于是体检可能招来一个真实对话根本不会撞上的 400。

误报和漏报一样坏——读者会去改一套本来没坏的设置。所以分不出类的 400 要再打
一枪，这一枪不带 `max_tokens`，形状和真实轮次一致。只在失败路径上多打，日常
一分钱不多花。

## 顺带三：判词改成覆盖层

`probeConfig` 在签名没变时会提前返回（那是它的节流），而 `probeHealth` 每次都
会重置 `this.health`。两者共用一个字段，就会出现「点是黄的、字却写着已保存」。
现在判词是 `paintBrand` 里的一层覆盖，不改写 `health`。

## 一个方法论上的教训

新加的四条体检闸**全在直调 `preflight.check()`**，于是漏掉了一个真实的 500：
`_slot_report` 要把码翻成文案，而「分不出类」那条文案带 `{detail}` 占位符，
而 `check()` 当时只回 `(码, 型号)`——`KeyError: 'detail'`。直调的闸一条都没红。

**闸得走读者真正走的那条路。** 补的 `test_the_endpoint_renders_every_code_without_blowing_up`
逐个码过一遍 HTTP，并断言渲染出来的句子里不含 `{`——漏一个占位符就是一个 500。
体检结论也从三元组换成了 `Verdict` 数据类：三个都是字符串的元组，位置解包迟早
会拧反，而拧反的后果是把节点的原话当成型号名显示出来。
