## ① 「漂开三版」——实际是**两个发布**

这个插件一共只发布过**三个版本号**，`versions.json` 的 key 就是完整清单：

```
0.12.13  →  0.13.0  →  0.13.1
```

实验室仓卡在第一个，公开仓在第三个——**区间横跨三个号，但落下的是两个发布**。

三条独立证据互相印证（我逐条复跑过）：

| 证据 | 内容 |
| --- | --- |
| `git log -- manifest.json` 逐提交取值 | `1362174`→`0.12.13` / `e30fac0`→`0.13.0` / `5e67545`→`0.13.1`，只有这三次 |
| `git log -- pen/__init__.py` 逐提交取值 | 完全同步的三次 |
| `versions.json` 的 key 集合 | `['0.12.13', '0.13.0', '0.13.1']` |

**中文「漂开三版」勉强能读成「横跨三个号」，英文那句不能**——
"has drifted three versions" 只有「落后三个」一个意思。而这条欠债的主题恰恰是
「版本号漂了没人盯」，数字本身写错一格特别扎眼。

这个错**长在 6 处**，其中后三处是 v0.15.11 就写下的，但 v0.15.13 把它搬进了
公开 README，这才第一次被读者看见：

| 位置 | 归属 |
| --- | --- |
| `README.md` / `README.en.md` 的欠债条 | v0.15.13 加的 |
| `docs/v0.15.11` 的追记 | v0.15.13 加的 |
| `pen/app.py` 的注释 | v0.15.11 |
| `pen/tests/test_app.py` 两处 docstring | v0.15.11 |

六处全改，并且**把清单写出来**（`versions.json` 的 key 就是完整版本史），
省得下次又有人重新数一遍还数错。

## ② `817ed79` 的括注挂错了对象

v0.15.11 的追记和 v0.15.13 都写着：

> 自 `817ed79`（v0.12.13，**也就是插件迁进公开仓那一刻**）起没再动过

- `817ed79` 是**实验室仓**的 `fix(v0.12.13): 下限就是可以静默丢掉的量`
- 「插件迁进公开仓」是**公开仓**的 `1362174 chore: transplant plugin source from the lab repo`，
  晚 29 分钟，**另一个仓的另一个提交**
- 而这两份文档随公开仓发：实测 `git cat-file -t 817ed79` 在公开仓里报
  `fatal: Not a valid object name`

改成「（v0.12.13，实验室仓最后一次动它）」，并在两份文档里各留一条追记说明改了什么。

**v0.15.14 那份文档只复核了「`817ed79` 确实是 v0.12.13」，没碰这半句**——
核对了断言的前半，漏了括注。记在这儿。
