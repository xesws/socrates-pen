# v0.18.7 — 旧 sidecar 占端口：Stop 是死的、Running 不验版本、存 key 404

> 日期：2026-08-23。评测三条同一条因果链：keep-alive 默认开，0.16 的
> `python -m pen` 占着 8765，插件 `ensure()` ping 通就标运行中，Stop 只杀
> 本次 spawn 的子进程（静默 no-op），PUT `/v1/llm/key` 404 被套成「起来再试」。

## 病

1. **Stop 是死的，Start 已在跑也没反馈。** `stopOwned()` 第一行
   `if (!this.owned || !this.child) return`。重载后 `owned` 回到 false；别人占着
   的端口、旧进程，一律静默。Start 在 ping 通时直接 `set("running")`，像没按。
2. **「运行中」不代表能干活。** ping 只看 `GET /v1/health` 是否 200。旧 sidecar
   有 health、没有 `PUT /v1/llm/key`，UI 照样运行中。
3. **存 key 报 Not Found / 未落任何文件。** 失焦即 PUT。404 走
   `noticeKeySaveFailed`：「sidecar 起来后再试」。失败按设计不写任何文件。
   迁移路径其实已有 `noticeSidecarTooOld`，设置页没用。

Key 写入/清除/重载、苏格拉底追问、写回批准、切笔记恢复——新 sidecar 上是通的，
不进这三条。保活默认开、整库可读、八拍深挖：有意不动。

## 改法

1. **Stop 按配置的 loopback 端口停。** 先 `POST /v1/shutdown`（新 sidecar 优雅退），
   仍在听就用 `lsof`/`ss`/`netstat` 找 PID，SIGTERM 再 SIGKILL。按钮：正在停止 /
   已停止 / 失败；Notice 说明是本插件拉起的、旧 python 残留、还是别的进程。
   **退出 Obsidian 仍只 `stopOwned`**（保活默认开，多库共用）。
2. **health 带 `version`（`pen.__version__`）。** 插件 `sidecarUsable`：缺版本或
   `cmpVer(sidecar, manifest) < 0` → 相位 `stale`，文案「旧服务占着端口，先停止再
   启动升级」，不标运行中。Start 已对齐 → toast「已经在跑」；仍是旧的 → toast
   先停再升，不假装成功。
3. **保存按钮**（回车/失焦仍可用）。`phase !== running` 时保存/清除禁用。404/405
   用「旧服务，先 Stop 再 Start」，不再说起来再试。失败输入留在框里；另在内存
   `pendingPutKey`（不进 data.json），升完自动 PUT。

独立 review（grok-4.6 xhigh）后补：面板 watch 只把 idle/error/stale 当挂，
`checking` 不把新 sidecar 打成连不上；`probeHealth` 同样验 version；
health/shutdown 2s 超时，404 的 shutdown 不再空等 2.5s 才 lsof。
