# v0.15.14 — 我把自己那道闸说早了一版

> 日期：2026-08-22。**这条是我自己查出来的**：写完 v0.15.13 之后，我怀疑其中一句话有问题，
> 在等审查回话的时候先自己去核，结果确实错了。

## 病在哪

v0.15.13 给 README「还欠着的」加的那条欠债里写着：

> 这个仓的 `manifest.json` / `package.json` / `pyproject.toml` / `pen/__init__.py` 四家同版，
> **v0.15.11 起有测试盯着**

**四家同盯是 v0.15.13 才有的。** v0.15.11 建那道闸时只断言了一家：

```python
# dd23f40:pen/tests/test_app.py
assert json.loads(manifest.read_text(encoding="utf-8"))["version"] == __version__
```

`package.json` / `pyproject.toml` / `versions.json` 那三条是 v0.15.13 才补的——
**而补它们的理由，恰恰是「v0.15.11 漏了这三家」**。所以这句话把 v0.15.13 存在的
全部理由给抹掉了，还顺带给读者一个假的保证期。

## 改法

中英各一句，改成「v0.15.13 起有测试一次盯全（v0.15.11 建这道闸时只盯了
`manifest.json` 一家，漏掉的三家正是下次发版会漏改的）」。

## 顺带补做的验证

v0.15.13 里我只变异了 `package.json` 一条就下了「变异验过」的结论。补齐另两条：

| 变异 | 结果 |
| --- | --- |
| `pyproject.toml` → `9.9.9` | `AssertionError: pyproject.toml：version = "9.9.9"` ✅ |
| `versions.json` 删掉 `0.13.1` | `assert '0.13.1' in {'0.12.13': …, '0.13.0': …}` ✅ |
| 三处还原后 | 绿，`git status` 干净 |

并确认 `versions.json` 的语义我理解对了：**版本号是这张表的 key，不是 value**
（value 是 `minAppVersion`）。

那次批量 `sed`（v0.15.13 改五份文档里的 `162` → `274`）我也自查了：
`docs/` 里没有残留的孤立 `162`，没有本该是 162 的地方被误改（`check-limits.mjs`
自己仍然打印 `162 项全部通过`），两份 README 确实不报 `npm test` 的总数。

`817ed79` 确实是 `fix(v0.12.13): 下限就是可以静默丢掉的量`——v0.15.13 文档里
那个提交号引对了。
