# v0.18.4 — 面板自动跟随活动笔记

> 日期：2026-08-23。0.18.3 复测：chip 视口 / 星号 / 丝带 / 错误气泡四项全过；
> 会话绑定四条未过，其中三条同根因——重定向只在跑命令时触发，光切笔记面板
> 纹丝不动。

## 改法

`PenView.onOpen` 注册 `workspace.on("file-open")`（obsidian.d.ts:8078），
活动笔记变化即把面板上下文切过去。重定向逻辑从 `captureSelection` 的
null-pick 分支抽成私有 `retarget(file)`，命令路径与自动跟随共用一份：

- 有绑定且会话存活 → `adopt` 恢复，跨笔记清引文/行号；
- 会话已被清理（isGone）/ 无绑定 → 清成该笔记空态（chips 随新会话回来）。

守卫：`file == null` 忽略；同笔记忽略；`busy || pending` 忽略（流式/审批
中途换上下文会污染在途轮次）。`registerEvent` 自动注销。

两路径唯一差异：命令路径保留 Notice（读者主动动作要反馈——恢复/已清理/
无选区），自动跟随**静默**（切笔记弹提示是噪音）。

## 复测四条的对应

| 复测 | 处置 |
| --- | --- |
| 只切笔记、没跑命令：旧内容还挂 | 自动跟随——切走即重定向，旧内容零残留（E2E 实测） |
| 无选中跑命令后 quote 仍挂、无 Notice | 无法从代码路径还原；自动跟随让切笔记的瞬间面板已切换，该场景整体消失 |
| 回原笔记线程不恢复 | 自动恢复绑定会话（E2E：切回 A，user 轮回来）；若那轮只有前端错误气泡则服务端本无线程——错误气泡是前端态、从不持久化，属预期 |
| 换选段后面板残留旧 quote | 同第一条，切走即清 |

## 审核追记（grok-4.6 xhigh 独立复审，发版前修毕）

首版判「先修再发」，五条 P1 全部成立并已修：

1. **在途重定向无代次**：加 `retargetGen`——每次 retarget 与捕获开始都领新代次，
   每个 await 后校验，过期即弃；跨笔记判定改为 await 之后现读现算。
2. **file-open 非 md 也跟随**：canvas/图片/embed 会把面板清空——handler 与
   retarget 双层 `extension !== "md"` 过滤。
3. **空态漏清旧 chrome**：A 的花销/状态/深挖书签/undo 会挂到 B 的开屏——
   空路径补齐 spend/usage/turnTokens/status/statusTipSig/deepNote/deepCursor/
   pending 归零 + refreshSnapshots。
4. **busy 期切笔记不补跟随**：「等回复时点了另一篇」正是最自然的切换时机——
   send/doApprove 的 finally 落定后 `followActiveFile()` 补一次。
5. **开面板不同步当前文件**：onOpen 末尾补 `followActiveFile()`——ribbon 打开
   直接是当前笔记的线程而不是开屏。

另修（P2）：命令路径无活动文件时补 errNoSelection；审批挂着时换目标会得到
「先处理审批」且不换上下文；「用当前选区」按钮在 pending 期间也置灰。

复审 E2E ship-bar 实测：canvas 打开面板不动；空态 spend/undo 零残留；
busy 解除后自动跟上；detach 面板重开同步当前文件；门禁全绿。
