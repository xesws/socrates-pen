## 病在哪

上一轮把 README 从 190 行做到 989 行，事实层面过了四轮复核，数字和引文都对得上代码与
真实 transcript。**但没有人检查它读起来是什么样。** 读者的原话是「全都是断句和莫名其妙
的东西，给人一种原地自嗨的感觉」「你就老老实实把这个项目介绍清楚就行了，就像你在做
presentation 一样」「不要搞那么多 bullet point」。

量出来的病根**不是 bullet 多**，是散文被切碎：全文 355 行散文切成 200 段，
**平均 1.78 行一段**——段落短到和 bullet 没有区别。所以光删 bullet 不会变好，
必须真的把相邻碎段并回段落。

## 写作规范（可逐条检查）

1. 每段 3–6 行，**禁止 1 行成段**（表格/代码块/引用块的引子行和收尾断言除外）
2. 每段最多 1 个破折号 `——`
3. 加粗节制，只给关键词，不当语气用
4. 第 1、2 节不出现版本号，不出现代码行号
5. 不写「我们曾经…后来改成…」这类开发日志句式
6. 不用 `⚠️` 开段
7. **但保留判断力**：真正的操作步骤和核对清单用列表更清楚，不机械地全改成散文

### 两个「不做」的判断

**§2 的五步编号列表保留，不改散文。** 读者反对的是「散文被切成伪 bullet」，不是反对枚举
本身。这五步有真实时间轴（划 → 点 → 答 → 后台并行 → 审批落盘），改成散文得靠「接着」
「然后」「与此同时」把顺序背下来，读者反而要在句子里数第几步。真正做的是另外三件：
加引子段和收尾段、删掉五步里那 8 处纯语气加粗、把「直接问」从芯片名单里挪出来。

**§4.10 一个字不改。** 它看着碎是假阳性——9 段里 4 段是表格/代码块的一行 caption，
caption 就该是一行；其余全在 `<details>` 里，是开发者参考材料，表格是正确形态。
4.5 那六条 `①`–`⑥` 同理保留：六条离散设计约束、每条配一段病因、且锁在折叠块里，
转散文会产出一堵 25 行的墙。

### 4.9 该杀的是版本号，不是过程

4.8 也用「第一版写错了，因为它是一条无界豁免」这个句式，那是全章语气，讲过程本身没问题。
真正该杀的是 `v0.15.0 → v0.15.4 → v0.15.7` 这三跳——读者一个都用不上，而「**有两条独立
的提示词路径，所以书名要注两次**」这件事本身就足以解释一切，不需要拿三个版本号当叙事支架。

## 顺带修掉的三处事实错误

重写时查出来的，逐条已实证：

1. **§2 把「直接问」列成芯片。** `pen/session.py:20-47` 的 `FIXED_CHIPS` 只有五枚：
   `socratic` / `explain_zero` / `examples` / `search`（`enabled: False`）/
   `writeback`（`enabled: False`）。`free` 是直接打字那条路，不是芯片。
2. **`.pen/` 对读者是错的路径。** `is_source_tree()` 要求 `pen/app.py` 存在**且**有
   `.git` 或 `pyproject.toml`；实测读者侧安装 `~/.socrates-pen/venv/.../site-packages/pen`
   存在但**没有 `pyproject.toml`**，所以 `PEN_DIR = ~/.socrates-pen`。实测该目录下只有
   `sessions/` 和 `venv/`，**没有嵌套的 `.pen/`**——原文「`~/.socrates-pen/` 下还有你的
   `.pen/` 数据」指向一个不存在的目录。只有从源码树跑的开发者才是仓库里的 `.pen/`，
   所以 4.8 那句「实测 `.pen/sessions/` 攒到 3389 个文件」和 3.7 的「作者本机 `.pen/`」
   都不用改。
3. **「唯一出网的是模型节点」缺前提。** §5 自己写着首次安装要从 GitHub 和 PyPI 拉依赖，
   所以改成「**装好之后**唯一出网的调用」。

另有一条推论现在敢写进 §2 了：教材缺「第三拍」小节时**只有 `vs_real` 一条轴死，另外四条
照常出题**。`probe.py:224` 注释原文即「书里没有叫「第三拍」的小节时白名单为空，那条轴就
永不出题」，而 `bridge`/`tradeoff`/`failure`/`altitude` 各自只看 `level_key`/`alt`/`trigger`，
没有一条碰 `beat`。
