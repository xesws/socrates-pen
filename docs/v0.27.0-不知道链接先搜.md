# v0.27.0 — 不知道链接先搜：自建 `search`，`fetch` 分段读

> 日期：2026-09-05。读者说：「网页只给了 fetch，它没法模糊搜索——模型必须知道具体的 URL 才能去取。
> 我希望它有基本的搜索功能，不用任何 API，不用 Firecrawl，不用 Tavily，自己去搜。」
> 又说：「注册工具的时候把 offset 和 limit 设计好，别一次返回一大堆；结果多的时候要筛、要排；
> 返回里要告诉模型还剩多少没看，它下一轮才能自己调参数把内容读完整。」

## 读者看到的

工具箱里只有 `fetch(url)`。模型要引一个网上的出处，先得**有**那个 URL；没有，它要么编一个链接去取、
要么假装搜过。会话模板里那句「没有地址就不要调用，也不要编一个链接再去取」是在替一个缺的工具兜底。

`fetch` 还有一个老问题：正文超过 5000 字符只写 `...(已截断)`，不说停在哪、下一段从哪读。0.26.0 给
`read_file` 修了这件事，`fetch` 没跟上。

## 实测：哪家入口不要钥匙

从读者机器直接打（浏览器 UA）：

| 入口 | 结果 | 结论 |
| --- | --- | --- |
| DuckDuckGo `html.duckduckgo.com/html/?q=` | 200，10 条真结果，标题 / URL / 摘要三样齐全，广告按 `ad_domain` 剔 | **首选** |
| Bing `www.bing.com/search?q=` | 200，10 个 `b_algo` 块，链接是 `bing.com/ck/a?…u=a1<base64>` 跳转串，要解码 | 备用 |
| Wikipedia `api.php?action=query&list=search` | 无钥匙全文搜索，中英都通 | 补充：概念题最准，最不怕被拦 |
| Brave HTML | 200 但 348KB、JS 重 | 不要 |
| Mojeek | 直接 Captcha | 不要 |
| cn.bing.com | 跳落地页，没有结果 | 不要 |

两个前提写在代码注释里：**UA 必须像浏览器**，工具自己的 UA 打 DuckDuckGo 拿到的是 202 挑战页；
这是它未公开的 HTML 入口，一秒打十次会被限流，所以一次 search 每家入口只打一个请求（正常两次：DDG 加
Wikipedia；DDG 倒了才有第三次 Bing），翻页从缓存切，同一个 query 并发只打一次。

## 规则一句话

不知道 URL → `search`（关键词，默认 5 条，最多 10 条，尾注说共几条、剩几条、下一段 offset）→ 挑一条
`fetch`（按段落编号，offset / limit 和 read_file 一个用法，尾注同款）。两个工具都是「结果先全拿到、就地缓存、
按 offset / limit 切片」，切片和尾注**只在 `pen/readtool.py::slice_lines` 定义一次**。

## 改了什么

### `pen/agent/search.py`（新）

- **三个入口**：`_ddg` 解 `result__a` + `uddg=`，摘要只在这条和下一条标题之间找（没摘要的结果不吞下一条）；
  `_bing` 按 `<li class="b_algo"` 切块，`ck/a?…u=a1<base64url>` 解回真 URL，解不出的丢；`_wikipedia` 按 query
  有没有 CJK 选 zh / en，失败静默。DuckDuckGo 非 200（不跟跳转，3xx 也算）、或零个 anchor 而页面没明说
  no results（挑战页、结构变了）→ 引擎倒了，才打 Bing；Wikipedia 总是打。三家响应都流式读，400KB 上限、
  8 秒墙钟；一条畸形 URL 只丢那一条。
- **筛**（`_merge`，O(n)）：只留 http(s)；字面 IP 是内网、`localhost` 的丢（复用 fetch 的两个判定，**不做 DNS**，
  真正的 SSRF 校验在 fetch 那一步）；按规范化 URL 合并（小写、去 `www.`、去 fragment、去 `utm_*` / `fbclid` /
  `gclid` / `spm`、去尾 `/`），两家都给的同一条合成一项、各家名次都留着；空标题丢；标题截 120、摘要截 200。
- **排**（`_rank`，O(n log n)，n ≤ 30）：Reciprocal Rank Fusion，`Σ 1/(60 + rank)`；关键词覆盖加成
  `0.0008 × (0.7 × 标题命中比例 + 0.3 × 摘要命中比例)`（拉丁按词边界、CJK 取二元组），只够翻过相邻一名、
  翻不了引擎的强信号；tie-break 按引擎顺序和名次，
  结果确定。实测「socratic method teaching」：Wikipedia 那条 DDG 第 2、Wiki 第 1，合起来排第一。
- **缓存**：模块级 `OrderedDict`，key 是压空白、小写、截到 200 字符的 query，TTL 600 秒、64 条，`threading.Lock`
  护着，同一 key 并发 single-flight。`offset > 1` 从缓存切，**不再打引擎**；失败不缓存；池过期后带旧 offset
  来的请求重搜一次并在开头说明。
- **分页与尾注**：`limit` 默认 `SEARCH_LIMIT_DEFAULT = 5`、收到 `SEARCH_LIMIT_MAX = 10`（`pen/config.py`，schema
  的 default / maximum、handler 的回落和收窄、尾注里「不超过」三处读它）。文本形状：

  ```
  搜索「q」：共 14 条，这里是第 1–5 条。
  1. 标题
     https://…
     摘要
  …
  （还有 9 条没看；接着看用 offset=6，limit 不超过 10。要读某一条的正文用 fetch，长页面按 fetch 的 offset / limit 分段。）
  ```

  最后一页写「已经是最后一条……不要重复搜同一个 query」；越界写「共 N 条，没有第 k 条起的结果」；零条写
  「没有结果，换更短、更具体的词」；三家都倒是工具错误「搜索入口暂时不可用」，只有 Wikipedia 有货时开头加
  一句说明。`offset` / `limit` 走 `tools_impl._int_arg`（同一定义点），`"L3"` / `true` 是工具错误，不打网。

### `pen/agent/fetch.py`

- `html_to_lines`：块级标签断行、行内空白合并、空行丢、`<pre>` 里按原换行；`html_to_text` 变成它的 join。
- `handle_fetch` 收 `offset` / `limit`（默认 `READ_LIMIT_DEFAULT`），取回的**行**按 URL 缓存十分钟（16 条，
  只缓存成功的），续读不再下载、不再走跳转链——第一次取时已经过了全套校验。超过 1500 字符的行进缓存前
  在空白处拆开，每行都读得到；200KB 处被截断的页面在读到末行时会说「后面的没取到」。切片和尾注调 `slice_lines(unit="页面")`，
  输出 `N\t段落`，`_line_span` 认得到，退批的 stub 能写「第 a–b 行」。实测 Wikipedia 一页 457 段，`limit=12`
  之后按尾注 `offset=13` 续读，下载次数仍是 1。

### `pen/readtool.py`

- `slice_lines(lines, offset, limit, *, unit, resume_hint)` 从 `read_file_report` 里抽出来，read_file 的输出逐字节不变
  （`test_readtool.py` 全部现有断言守着）。

### 其余

- `pen/agent/registry.py`：`SEARCH_SCHEMA`；`fetch` 描述改成「没有 URL 先用 search，不要编链接」并加 offset / limit。
- `pen/agent/permissions.py`：`search` 和 `read_file` / `fetch` 一样 allow；`_remember_read` 只认 read_file，
  搜和取都不给 edit_file 资格。
- `pen/overflow.py`：退批文案里 `fetch` 改成「同一 URL 带 offset 和 limit 分段取」，新增 `search` 分支；
  `path` 记 query。
- `pen/session.py` 两份模板：「网上的东西：已有 URL 直接 fetch；没有 URL 先 search（写关键词，不是整句问题），
  从结果里挑一条再 fetch 取正文。长页面按 fetch 尾注给的 offset 分段读。不要编链接，不要假装搜过，
  同一个 query 不要反复搜。」
- 插件：`kickerSearchTool`「搜网页」/ "search"，日志区一条「搜网页 → <query>」。

## 四审：Codex review 后修的

发版前照老规矩用 Codex（gpt-5.6-sol，xhigh，只读沙箱）审了 feat 整段 diff：没有 high，10 条 medium、
2 条 low，全修，每条先红后绿：

- **medium · `follow_redirects=True` 让「search 只打写死主机」不成立。** 入口回一个 Location 就会去请求
  没校验过的主机。修：关掉跟跳转，非 200（含 3xx）一律当引擎倒了。
- **medium · 解析失败没有退化。** DDG 结构稍变得到零个 anchor 会被当成真零条，不换 Bing；一条畸形 URL 让
  `urlparse` 抛出来，整批作废；Wikipedia 的 JSON 形状不对在 try 外抛。修：零 anchor 只有页面明说 no results
  才是零条，其余算倒；每条结果单独兜底（`_well_formed`）；Wikipedia 逐层验类型。
- **medium · 分页元数据谎报。** 先按整段 chunk 算 range 再把文本硬切到 `MAX_OUTPUT`，长 URL 能让正文在某条
  中间断掉、尾注消失。修：逐条在预算内追加、给尾注留 260 字符，range 只报真交付的，被预算截住时尾注说
  「这一段先到这里」；query 先截到 200，URL 超过 400 的不要。
- **medium · 查缓存→打引擎→写缓存不是 single-flight。** 并发 miss 各打一遍；池过期后带旧 offset 来的请求
  静默重搜、序号漂移。修：按 query 加 in-flight 锁；`offset > 1` 却要重搜时开头写「结果池已过期，重新搜了一次」。
- **medium · 200KB 字节上限没传到切片层**，「页面共 N 行」在撒谎。修：`_read_capped` 带回 capped 进缓存；
  读到手里的最后一行或越界时加「这一页超过 N 字节，后面的没取到」；截断时丢掉可能切了一半的末行。
- **medium · 超过 `MAX_OUTPUT` 的单个段落只给开头、剩余永远读不到。** 修：进缓存前把超过 1500 字符的行在
  空白处拆开（无空白硬切），拆行点稳定，每行都读得到。
- **medium · 退批 stub 只对 read_file 算行号区间。** fetch 已是 `N\t段落`。修：两者都算。
- **medium · 模板「网上的东西先 search」和 schema「有 URL 就 fetch」打架。** 修：「已有 URL 直接 fetch；
  没有 URL 先 search」，英文同。
- **medium · 覆盖加成太重。** 0.003 能让第 10 名翻到第 1；标题摘要是站点可操纵的；拉丁词子串匹配。修：
  0.0008，标题占 0.7、摘要 0.3，拉丁词按词边界；第 2 名标题全命中刚好翻过第 1，摘要全命中翻不过，
  第 10 名全命中翻不过第 1。
- **medium · 三家响应整个进内存、没有字节上限和墙钟。** 修：`_get` 流式读，400KB 上限，8 秒墙钟。
- **low · 规范化键丢 scheme 且保留先来的 URL**，可能把 http 交给 fetch。修：合并时 https 优先。
- **low · 文案还写「三个工具」「一次只打一个请求」。** 修：preflight 注释改四个工具；search 文档写清
  正常两次、降级三次。

## 没做的

- `fetch` 的 UA 仍是 `socrates-pen fetch`：很多站对非浏览器 UA 回 403，要不要也换成浏览器 UA 等读者定
  （那是「取」不是「搜」，行为面更大）。
- 不做 DuckDuckGo 第二页、不加更多引擎：一个 query 三家合起来 15～25 条，够挑。
- 不做「搜完自动取第一条」：挑哪条是模型的判断，取正文的成本要留在它看得见的地方。
- 网页正文不去导航栏：Wikipedia 前十几行是「Jump to content / Main menu」，模型按尾注往后翻就是；
  真要去，得按站点写规则。
- 侧栏那颗「查相关论文 / 算法出处」芯片这一版没动。
- 搜索会把 query 发到 DuckDuckGo / Bing / Wikipedia，这是任何网页搜索都免不了的；设置页不加开关，和 fetch 一个待遇。
