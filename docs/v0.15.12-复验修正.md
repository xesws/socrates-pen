## ① 「不点写回，它一个字都不会往你笔记里放」——结论对，理由错

这是公开 README 里读者**唯一会拿来当安全边界**的一句话，所以它排在最前面。

原文：「写回是**一枚要你主动点的芯片**，而且点完还得再过一次审批。」

**`free` 芯片也能提编辑，完全不用点写回。** `pen/session.py:64` 就是这么写的：

> free：看用户怎么问。若要改手册，同样先 read_file 拿到返回再 edit_file，同一轮里做完。

**物证在我自己仓里**：`docs/demo/transcripts/08b-approve-deny.json` 的 `chip` 是
**`free`**，`user_text` 是「在决策① 那三层解释后面，补一句一行小结……」，
它照样吐出了 `edit_file` 的 `approval` 事件。**README 里 3.5 那段拒绝演示，用的就是它。**

结论那半句（「一个字都不会往你笔记里放」）是对的，但兜住它的是**审批闸**
（`pen/agent/permissions.py:15` 的 `decide("edit_file") == "ask"`，对每一枚芯片都成立），
不是「你没点那枚芯片」。读者照原话读，会以为不点写回就绝对安全，然后在 `free` 里
打一句「帮我在那段后面补一句」，当场撞上审批弹窗。

改成把闸门摆在前面，并把 `free` 那条路和 `08b` 的链接一起写出来。
