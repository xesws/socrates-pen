# v0.21.0 — 自定义泡泡（自定义插入模板）

> 日期：2026-09-01。插件 `0.20.0` → `0.21.0`。

侧栏底座那排按钮（读者口中的「泡泡」，代码里叫 chip）原来是写死的五枚。
每一枚底层就是一次 **prompt injection**：点下去只发一个字符串 id 给 sidecar，
sidecar 按 id 在一张表里查出一句自然语言指令，拼进 user packet 的 `[意图]` 段。

这张表是作者写死的，而真实读者有作者穷举不完的体例需求。最典型的那一类是：

> 让 AI 把问题插入到 questions section，格式必须是 `<details>` 这种可展开的标准化格式。

形状固定——**一段读者自己写的 prompt + 一次会改写原文的写盘**——只是每个人的体例不同。
所以这一版做的不是再加几枚固定芯片，而是把「芯片 = 一段注入的 prompt」这件事开放出来。

**格式校验这一版不做**，只留扩展点（`CustomChip.format`，写而不读）。
`pen/insert.py:32` 已有现成的 `lint_fold()`，下一个小版本再接。

## 一、四个拍板

| # | 决策 | 理由 |
|---|---|---|
| 1 | 存 Obsidian 设置页的 `data.json` | 复用现有 `PenSettingTab` + `loadData/saveData`，模板跟着 vault 走、可随库同步。**后端对自定义芯片全程无状态**，prompt 随每次 `POST /v1/chat` 上行，不新增存储、不新增端点 |
| 2 | 每枚泡泡一个「会改写原文」开关 | 开着时后端追加内置写回纪律；不开的话模型第一次 `edit_file` 必被 `pen/agent/permissions.py` 的 read-first 硬闸打回，白跑一轮 |
| 3 | 预置三个起手模板，一键复制后再改 | 拿到就能跑，也直接示范了折叠格式该怎么写 |
| 4 | 格式校验只留扩展点 | 先跑通。`lint_fold()` 的空行契约是给那本手册的体例定的，硬接上去会误杀读者自己的格式 |

**决策 2 的边界必须说清，别把话说满。** 这个开关只控制**注入的纪律文本**，不控制工具可见性：
`pen/tutor.py` 的 `tools = schemas()` 恒给三个工具，所以关掉开关的泡泡，模型仍**可能**提出一次
`edit_file`。磁盘安全由**审批闸**保证（`edit_file → ask`），不由这个开关保证——
这和现有 `free` 芯片的行为一致，README §3.3 早就写明了这一条。

## 二、改了什么

### 后端

- **新模块 `pen/chips.py`**。`CHIP_INTENT` 和 `chip_intent()` 从 `pen/tutor.py` **整体搬过来，不留别名**
  （留别名就是第二个定义点，`tutor.py` 关于 `MAX_TOOL_ROUNDS` 的注释早把这条家法写死了）。
  新增 `CustomChipSpec` / `normalize_custom_chip()` / `custom_intent()` / `sanitize_prompt()`。
- `build_user_packet()` 加关键字参数 `custom`，`[意图]` 段的正文改成
  `custom_intent(custom, lang) if custom else chip_intent(chip, lang)`。段的结构一个字没动。
- `ChatBody` 加 `custom_chip: dict[str, Any] | None`。
- `chat()` 里 `shown` 优先取 `custom.label`——`chip_label()` 只认 `FIXED_CHIPS`，
  查不到**返回 id 本身**，不接这一手的话读者的气泡会显示成裸 `u.a1b2c3`，而且**落盘进 `ui_messages`**。
- `should_probe()` 加必填参数 `writeback`：勾了写回的那一轮不是学习轮，不该白烧一次后台深挖。
  **故意做成必填而不是给个默认值**——这个纯函数的判定条件得自己说得清。
- system prompt 中英两版各加一行「以 `u.` 开头的是读者自己定的芯片，照 `[意图]` 段那段做」。

### 前端

- 新文件 `src/customchips.ts`（类型 + 归一化 + 消毒，纯函数、不 import obsidian）
  和 `src/chippresets.ts`（三个预置模板）。
- `PenSettings.customChips`；`loadSettings()` 里**显式深一层展开**（和那里对 `limits` 的处理同源）。
- `paintChips()` 把自定义泡泡渲染在固定芯片之后、动态追问之前，带 `is-custom` 一档视觉；
  `chipsSig` 把它们算进签名。
- 抽出 `labelOf(chipId)`，两张表都查。
- 设置页新增「自定义泡泡」一节：每枚一个 `<details>` 内联编辑区，底下一行「从模板新建」。
  **全程不调 `this.display()`**——那是这个文件的家法，重画会把正在编辑的 textarea 的
  焦点和光标一起吃掉，而这一节里读者恰恰是在长文本框里逐字打字。
- 新闸 `scripts/check-chips.mjs`（71 项），进 `npm test` 链。

### 审批链路一行没改

自定义写回芯片产出的 `edit_file` 走的还是
`tutor._run_tool_batch()` → `session.pending` → SSE `approval` → `paintPanel()` →
`POST /v1/chat/approve` → `resume_chat()`。快照、撤销、`revealInsert` 全部自动生效。

## 三、做的过程中挖出来的三个真问题

这一版有意思的部分不在功能本身，在于「让读者写的字进 packet」这件事把几个**旧的**
薄弱处顶出了水面。三个都不是新功能引入的，但都是新功能会天天踩到的。

### 1 · `compact` 的段头解析没锚行首，「defang」原本是做样子的

`pen/compact.py` 的 `_section_named()` 用的是

```python
re.search(rf"\[{re.escape(name)}[^\]]*\]\n(.*?)(?=\n\[|\Z)", content, re.S)
```

起头**没有 `^`**，而结尾那个 lookahead `\n\[` 倒是锚在行首的——两头不同源。
后果是：正文里随手一句「见 [框选] 那段」既能凭空开出第二个「框选」段，
又能把真的那段提前掐断。

原来这只是「理论上」，因为 packet 全是 `build_user_packet()` 拼的，段头永远在第 0 列。
**v0.21.0 起 `[意图]` 段里会原样带上读者自己写的那段 prompt**，于是它变成「一定会遇到」。

`sanitize_prompt()` 的做法是给行首的 `[段头]` 前面塞一个空格（只 defang，不删字）。
但这招**只有在消费方锚了行首之后才成立**。所以两头一起改：`_section()` 和
`_section_named()` 都加 `^` + `re.M`。真实 packet 一个字都不受影响，纯硬化。

`pen/tests/test_chips.py` 里配了三条测试：defang 生效、真段不被顶掉，
外加一条**反证**——不消毒的同一份内容真的会被顶掉，证明前两条测的是真闸、不是恒真式。

### 2 · 消毒里 `strip()` 排在 defang 后面，最该防的那一格恰好漏网

`sanitize_prompt` 原来的顺序是「先 defang 再 strip」。
prompt 第一行就是 `[框选]` 的那一格里，塞进去的空格正好落在字符串开头，
被 `strip()` 清得干干净净——而「读者从别处整段粘过来、第一行就是段头」恰恰是最可能发生的一格。

前后端两份消毒**顺序必须一样**，两边都改成 defang 排在 trim 之后。
是新闸 `check-chips.mjs` 跑出来的第一条红。

### 3 · `CHIP_INTENT["writeback"]` 和 SYSTEM_PROMPT 互相矛盾（**旧债，这一版没还**）

`CHIP_INTENT["writeback"]` 写的是「下一轮再单独 `edit_file`」，
而 `SYSTEM_PROMPT_TEMPLATE` 写的是「这两步在同一轮里接着做完」。两句话对着干。

这一版**没有复用**那条纪律，而是照 SYSTEM_PROMPT 的说法另写了一份 `WRITEBACK_DISCIPLINE`。
理由：三个预置模板全都勾着写回，等于让新功能的默认路径去踩一条已知的矛盾。
旧的那条一个字没动（动它要重跑写回那一整条链的验证，不是这一版该背的），
但在 `test_chips.py` 里留了一条回归闸盯着它的措辞，**下一版必须有人来把这两句话对齐**。

顺带把 details 那句硬约束澄清了一个字面：折叠块只放进 `edit_file` 的 `new_string`，
别在聊天里再贴一遍——`src/foldview.ts` 的 `visibleReply()` 会把回复里的
`<details>/<summary>` 剥掉，模型要是两边都贴，读者看到的是半截结构，会以为「它没听我的」。

## 四、顺手校准的两处

- `scripts/check-i18n.mjs` 的 `FLOOR` 写着 `{files: 11, err: 7, notice: 10}`，
  而真数早已是 `15 / 10 / 35`。`notice` 那格富余 25 个，这条闸形同虚设——
  正是它自己那段注释警告过的「防瞎闸一个字不说」。按它写明的维护契约
  （「下限必须是今天的真数」）一次归位。
- README 的规模表和三处「524 passed」是几版之前的数，一并按今天的真数改。

## 五、有意不做的三件事

1. **动态追问的去重表不并入自定义 label。** `clean_candidates(fixed_labels=…)`
   要透一个字段过 `stream_chat → ctx → _finish_text`，而 `resume_chat` 自建 ctx、拿不到它，
   透一半就是新的漂移点。收益只是「读者的按钮文案和模型的追问长得像」这种低概率观感问题——
   自定义 label 是短按钮词，动态追问是问句，`similarity ≥ 0.55` 很难命中。不值这条线。
2. **「会改写原文」不裁工具表。** 要按芯片裁工具，得沿 `stream_chat → _agent_loop` 透标志，
   `resume_chat` 那半轮也要同样处理，否则同一轮前后半段工具表不一致。
   磁盘安全本来就由审批闸兜住，裁工具只省一次「模型提议 → 读者拒绝」的往返。
3. **不给自定义芯片加「先有一轮实质解答」的前置闸。** 加上去会把模板一
   （只需要框选就能出题，正是读者点名的头号场景）一起锁死。
   改成让模板正文自足：模板二写明「刚才聊过就复用，没聊过就现在讲清楚」。
