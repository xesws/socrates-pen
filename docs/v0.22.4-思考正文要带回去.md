# v0.22.4 — 思考正文要带回去

> 日期：2026-09-02。承读者的一张截图：Fast Mode 绊线换回基座，当场 400。

## 读者说的

> 「从 fast-mode 切换回原始模型的时候会报 API error，应该是 API 格式传的
> 内容有问题。」

截图里的红字是节点的**原话**：

```
The `reasoning_content` in the thinking mode must be passed back to the API.
```

## 这不是 Fast Mode 的病

`_StreamedMessage.model_dump()` 一直只吐 `content` 和 `tool_calls`。思考流那
一路只被数了字数（`think_chars`，用来让状态行跳数字），**正文当场扔掉**。

于是任何「模型调了一次工具、下一枪接着说」的对话，第二枪都会把一条缺
`reasoning_content` 的 assistant 消息发回去。开着 thinking 的节点当场 400。

复现两遍，一模一样：

| 场景 | 结果 |
|---|---|
| Fast Mode 撞绊线换回基座 | 400 |
| **纯基座、没开 Fast Mode、thinking 开着、翻了一次手册** | **同一个 400** |

Fast Mode 只是让它变得**必然**——快模型总是先 `read_file` 再交班，所以基座
接手时历史里一定有一条带 `tool_calls` 的 assistant 消息。

而它直到 `v0.22.3` 才看得见：在那之前，这条 400 被渲染成「节点拒绝了这次
请求。请核对设置里的 Base URL、model 字符串和 API Key」——**三样都是对的，
读者只会一遍遍去核对没坏的东西。** 上一版把节点原话转述出来，这一版才拿到了
病灶。

## 改法

`pen/reasoning.py`（新）：思考正文的去留，一个模块管到底。

```python
MAX_CHARS = 8000          # 单条封顶
FIELD = "reasoning_content"
def clip(text) -> str     # 封顶
def forget(messages)      # 摘掉（新一轮开始时 / 落盘时）
def chars(messages) -> int
```

四个接线点，各在一个地方：

| 在哪 | 做什么 |
|---|---|
| `_create` 收流 | 累加思考正文，边加边封顶 |
| `_StreamedMessage.model_dump` | 有正文就带上 `reasoning_content` |
| `stream_chat` 追加 user 之前 | 忘掉之前所有轮次的思考正文 |
| `session.to_dict` | 落盘不写（和像素同理） |
| `compact.message_chars` | 算进窗口估算——它是**真上线的字节** |

### 只有自己在思考模式里才带回去

```python
def thinking_on(model: str, level: str) -> bool:
    """**从 thinking_wire 推导，不另写一张表。**"""
```

「UI 的 off 对某些型号仍是开着的」这件事只有 `thinking_wire` 知道
（`_glm_forced_thinking` 那一支：GLM-5.3 关不掉思考，off 映射成 enabled + 最低
档）。另写一张表，那一格必然写错。关着思考的节点没要过这个字段，就别塞。

### 换了模型也照传

绊线换回基座时，历史里那条带 `tool_calls` 的 assistant 消息是**快模型**产的。
照传它的思考正文看着别扭，但那恰恰是事实：**就是这段推理导出了那次工具调用**。
OpenAI 兼容的 `reasoning_content` 只是个字符串，没有签名、没有归属校验；摘掉
它反而会让基座又撞回同一个 400。

### 为什么封顶、为什么遗忘

思考正文实测能到上千个分片，而 `_agent_loop` 每一枪都重发整段历史。不封顶就是
按轮次翻倍地烧钱，还会撑破快模型那道硬窗口闸。而「必须回传」这条契约只约束
**当前这条工具链**——新一轮 user 消息一到，之前的推理没人要了，当场忘掉。

## 一个夹具上的教训

新写的闸第一版是绿的，但它测的是幻觉：`_Recorder` 存的 `messages` 是
`session.messages` 的**活引用**（没图时 `strip_images` 原样返回那个 list），
所以跑完再看到的是终态，不是当时发出去的那一枪。

改成当场快照之后，两条老断言红了——它们用 `is sess.messages` 来证明「基座
路径不做副本」。那个保证仍然值得守，改成比对 `id()`，两件事各自成立。

**闸要看的是「真发出去的那一枪」，这句话对存引用的夹具同样成立。**
