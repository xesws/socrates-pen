# v0.22.1 — 降级不再是无声的

> 日期：2026-09-02。修 `v0.22.0` 的一处报告缺陷。

## 读者报的现象

> 「Fast Mode 开启之后，我再把它关掉，然后重新设置、重新配了一下它的 API 站点，
> 接着再配回来。这个时候，Fast Mode 就再也没法启动了。虽然表面上显示启动了
> Fast Mode，但是它每次都会路由到主要的模型上。这说明它背后肯定是有错误，
> 但是我们的错误却没有被 raise 出来，导致我不知道它到底有没有降级。」

## 病灶

钥匙是**和它所属的主机一起**落盘的（`llm.json` 里 `fast_api_key` 与
`fast_base_url` 成对）。`_merge_over` 的跨主机保护据此工作：请求要去 A，槽里
那把是给 B 的，就返回 `None`——**这条保护是对的**，`data.json` 一旦被改坏，
没有它就会把钥匙送去任意主机。

复现路径踩的是这条保护的边：设置页显示着 B 时按了保存，槽里记下的就是 B；
之后把输入框改回 A 却没有重新保存，于是请求主机 A ≠ 槽里主机 B。

问题不在保护，在**这件事一个字都没说出来**。三处都在替它掩盖：

| 位置 | 当时的样子 |
|---|---|
| `app.py` 路由调用点 | `route, _route_why = route_for(...)` —— 理由算出来了，就地扔掉 |
| `fast_public_status()` | 回答的是「槽里有没有钥匙」，不是「Fast Mode 能不能用」 |
| 设置页 / 顶栏开关 | 都信了上面那个 `ok`，于是状态行一直显示「已保存」 |

三处叠起来的效果就是：开关亮着，状态行说配好了，每一轮却都悄悄走基座。
**读者唯一能观察到的差别只有「没变快」**，而这恰好和网络慢、和快模型本身
不够快长得一模一样。

## 改法

让「配没配成」和「为什么没配成」同源，然后一路带到读者眼前。

```python
# pen/config.py —— 唯一定义点
FAST_NO_KEY  = "no-fast-key"
FAST_HOST_GAP = "fast-host-mismatch"

def fast_llm_status(...) -> tuple[LLMConfig | None, str]:
    """快模型这一路的 cfg **和它没配成的理由**。配成了理由是空串。"""

def merge_fast_llm(...):
    """只要 cfg 不要理由的调用方用这个；**实现只有 fast_llm_status 一份**。"""
    return fast_llm_status(...)[0]
```

`route_for` 原来收的是 `has_fast_cfg: bool`——一个布尔装不下两种失败，改成
收 `fast_why: str`，它成为路由理由本身，不再另起一套名字。`app.py` 在
`gen()` 里把这个理由发成 `route` 事件；前端 `insertRouteNote` 逐条认，
`no-fast-key` 说「去填」，`fast-host-mismatch` 说「**在当前这个站点上重新存一次**」
——两句话指向的动作不一样，混着说等于没说。

顺手把「这把钥匙是不是给另一台主机的」抽成前端唯一的一份 `keyHostGap()`，
基座那格现成的提示改成调它，快模型那格和顶栏开关复用同一个：

```ts
export function keyHostGap(status, settingsUrl): [string, string] | null
```

它只是**提示**不是闸——真判定在 sidecar 的 `fast_llm_status()`。前端自己再长出
第二份比对，就成了「两个闸不同源」。

## 说话的三个时刻

| 时刻 | 说什么 |
|---|---|
| 设置页 Fast Base URL 失焦 | 当场 Notice：钥匙是给 X 的，现在要去 Y，请在 Y 上重存 |
| 点亮顶栏开关 | 同上（区分「没钥匙」和「钥匙不对主机」两种话术） |
| 每一轮真的降级时 | 对话流里插一条 `route` 注记 —— **这条是兜底**，前两处都错过了也逃不掉 |

第三条才是这次修复的核心：前两处是「改配置的那一刻提醒」，只有它盯着的是
「这一轮到底跑在谁身上」，而那正是读者问的问题。

## 新增回归闸

- `test_config.py::test_a_key_saved_for_another_host_reports_a_mismatch_not_a_missing_key`
  —— 把读者那条复现路径逐步编码进断言
- `test_app.py::test_a_broken_fast_config_is_reported_not_swallowed` —— 降级必须发出 `route`
- `test_app.py::test_a_working_fast_turn_stays_quiet` / `test_a_writeback_turn_does_not_cry_wolf`
  —— 反向闸：配好了、或本来就该走基座的轮次，不许乱喊
