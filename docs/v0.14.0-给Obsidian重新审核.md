# v0.14.0 — 打一版新 Release，给 Obsidian 重新审核

> 日期：2026-08-22。插件 semver `0.13.1` → `0.14.0`。发 GitHub Release，
> 三件套 `main.js` / `manifest.json` / `styles.css`。sidecar 从同一 tag 的 zip 装。

## 为什么不是改 0.13.1

0.13.1 是 9 小时前那次审查修复。之后 main 上是整份 README 重写（苏格拉底学习法的
两面：你追问、它追问），加上 v0.15.0 把教材从 system prompt 里解耦。Obsidian
审核员如果 checkout 的是 **tag**，0.13.1 里还是旧开篇。GitHub 不允许把已发布
版本的 tag 挪到 HEAD 而不制造混乱，所以下一号是 `0.14.0`。

## 版本号要一起动的五处

闸在 `pen/tests/test_app.py::test_all_four_version_sources_agree`：

| 文件 | 字段 |
| --- | --- |
| `pen/__init__.py` | `__version__` |
| `manifest.json` | `version` |
| `package.json` | `version` |
| `pyproject.toml` | `project.version` |
| `versions.json` | 增加 `"0.14.0": "1.5.0"`，旧 key 保留 |
| `package-lock.json` | 顶层和 `packages[""]` 的 `version`（会进 tag zip；闸也盯它） |

`FastAPI(version=...)` 读 `__version__`，不手改。历史文档里的 `0.13.1` 是当时的事实，不动。
