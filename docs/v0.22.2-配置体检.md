# v0.22.2 — 配置体检：状态栏第一次真的知道行不行

> 日期：2026-09-02。承读者的一张截图：同一场对话里连着三种红字。

## 读者说的

> 「我明明把图像理解给关了，为什么不生效呢？它还是有图像理解……不管我们是改
> base URL、模型名，还是做图像理解的切换，所有的设置都必须支持热插拔、热生效。
> 如果它不生效，你必须得有反应……我根本不知道 OpenAI Key 到底配好没有，或者
> 这个节点是否拒收图片。所有这些 error 的情况，目前状态栏都显示完全正常。」

截图里三种红字依次出现：「找不到模型配置」→「意料外的错误（NotFoundError）」→
「节点拒收了图片」。**错误在变，说明 base URL / 模型名的热切换是生效的**——
那三条红字正是三套不同配置的真实回声。真正坏掉的是另外两件事。

## 病灶一：「图像理解」这个开关，对贴过图的会话完全无效

`tutor.py` 入口那道闸只拦**这一轮新贴的图**：

```python
pics = list(images or [])
if pics and not cfg.vision:
    yield {"type": "error", ...}
```

可 `session.messages` 是**常驻内存**的（`SessionStore._items`）。上一轮贴的
`image_url` 段跟着每一枪原样重发，于是读者关掉开关之后，节点照旧收到那张图、
照旧拒收。他没贴新图，却一直在被拒——看起来就是开关坏了。

改法：摘在**唯一的发枪点**上，非破坏。

```python
wire = session.messages if shot is None else shot
kwargs = llm_create_kwargs(cfg, messages=wire if cfg.vision else strip_images(wire), ...)
```

摘在这里而不是入口，有两个理由。一是这里是唯一的发枪点；二是 `cfg` 会在
Fast Mode 换模型时重绑——**快模型没视觉、基座有视觉时，同一段历史该发什么，
只有这一枪自己知道**。

非破坏也是有意的：读者关掉开关只是说「这一路别发图」，不是说「把我贴过的图
烧了」。再打开时那些像素还在会话里（`test_the_pictures_survive_in_the_session`
钉着这一条）。`strip_images` 在没有图时原样返回同一个 list，零成本。

## 病灶二：状态栏检的两件事，和读者关心的那件事无关

| 显示 | 它真正在检 |
|---|---|
| 顶栏那颗点 | sidecar 进程活没活（`sidecarReachable`） |
| 设置页状态行 | `llm.json` 里有没有那一行钥匙 |

钥匙是废的、model 在这个节点上不存在、节点根本没有视觉——**这三件它一件都
不检**。所以「显示完全正常」是诚实的：它检的那两件确实正常。

这也是为什么读者只能靠撞红字来发现问题：唯一会真往节点打枪的地方，是对话本身。

## 改法：一条会真打枪的体检

新端点 `POST /v1/llm/preflight`。发一条最小的真请求——`max_tokens=1`、
不带工具、一句 `hi`；**开着「图像理解」时挂一张 1×1 的 PNG**，因为
「这个节点收不收图」只有把图递过去才知道。

字段全部继承 `LlmOverrideBody`：体检的必须是**读者此刻设置页里填的那一套**，
和 `/v1/chat` 逐字同源。另立一套字段就会出现「体检过了，真发一轮还是错」。

错在哪不自己判，交给 `tutor.provider_error_code()`——那是「节点这一下为什么
失败」的唯一定义点，对话里的红字气泡用的也是它。顺手把 **404 从「意料外的
错误」里拆出来**：在 OpenAI 兼容节点上它几乎只有一个意思，就是这个节点没有
这个型号。读者截图里那条 `NotFoundError` 就是它。

| 码 | 读者看到的 |
|---|---|
| `no-config` | 还没填钥匙 |
| `bad-key` | 节点不收这把钥匙 |
| `no-model` | 这个节点上没有 `{model}` 这个模型（404） |
| `no-vision` | 节点拒收了图片，把「图像理解」关掉或换多模态模型 |
| `unreachable` | 连不上节点，检查 Base URL |
| `fast-host-mismatch` | 钥匙是给另一个站点的（v0.22.1 那条，本机就能判，不打枪） |

## 花钱的纪律

体检是一次**真实的 API 调用**，而 `probeHealth()` 每划一次选区就会被调一次
（`captureSelection` 里那一句）。所以拦着它的是一个签名：

```ts
export function configSignature(s, keyTail, fastTail): string
```

八项——节点 / 型号 / 视觉 / 快模型那三格 / 两把钥匙的末四位——任何一项变了
才重新体检。钥匙末四位在里面，是因为「刚换了一把钥匙」也得重验，而钥匙本身
前端拿不到。

`scripts/check-preflight.mjs`（新，进 `npm test`）守两个方向：八项里漏一项 =
那一项的热切换失效；多算一项 = 读者按选区被计费。

真正的调用时机只有这几个：开设置页、Base URL / model 失焦、翻「图像理解」、
存钥匙、面板发现配置变了。**不进任何轮询。**

## 顶栏那颗点，现在是三档

```
绿  连得上，且这套配置真的能用
黄  连得上，但配置是坏的  ← 以前这一档不存在，和绿共用一个颜色
红  连不上 sidecar
```

## 新增回归闸

- `test_vision.py::test_turning_vision_off_stops_sending_old_pictures`
  —— 断言看的是**真发出去的那一枪**，不是会话。看会话的话，把图从历史里删掉
  也能让它变绿，而那是另一种（破坏性的）行为。撤掉修复这条当场红。
- `test_preflight.py` 七条 —— 起一个真 HTTP 假节点，按 key / model / 有没有图
  分别回 401 / 404 / 400。**用真 HTTP 而不是 monkeypatch openai**：体检的全部
  价值就在于它真的打出去了，桩掉网络等于在测一个和线上无关的幻觉。
